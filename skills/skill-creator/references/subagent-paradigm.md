# 统一子代理委派约定 - 所有含子代理技能共用的结构、跨平台协议与改造流程

## 核心定位

不同宿主环境（pi、Claude Code、Codex、OpenCode）的子代理注册目录与配置格式互不兼容，但它们都支持按相对路径读取技能目录内的文件，并具备无需预先注册即可启动的内置通用子代理工具。

本文件将技能内的子代理委派落实为一套跨平台统一约定：**在 `SKILL.md` 中声明通用调度协议与轻量结构化调用卡，在 `agents/<role-id>.md` 中内聚该子代理的专属调度配置、上下文白黑名单、状态码闭环表与纯提示词块。** 所有含子代理的技能都按这一套编写，既无需依赖任何宿主私有的子代理注册目录，也不会在各业务技能的 `agents/` 下遗留冗余模板文件。

> 本文件是 SKILL.md `## 统一子代理委派（--subagent）` 小节的展开。

---

## 一、约定

| 项目 | 约定 |
|------|------|
| 存放位置 | 技能目录下的 `agents/<role-id>.md`（`role-id` 使用 kebab-case，与文件名一致） |
| 目录纯净性 | `agents/` 目录下**只允许**存放运行时真实会被派发的子代理文件，**严禁**存放 `template.md` 等编写期模板文件（编写模板统一由 `skill-creator/assets/subagent-kit/` 提供） |
| 主从受众隔离 | 每个 `agents/<role-id>.md` 分为两层受众：<br>1. **主代理层（YAML 头部 + 第 1–3 节）**：模型档位、权限与并发配置、输入白黑名单、结果验收与状态闭环表，仅服务主代理；<br>2. **子代理层（第 4 节 ```` ```prompt ```` 代码块）**：填充占位符后发送给子代理的全部提示词。**严禁**把第 1–3 节内容写入任务提示词或传给子代理 |
| 通用调度去重 | 等待去重、超时处理、禁止回问、禁止嵌套派生、无法派发时的降级防伪等跨角色共性规则，统一写在 `SKILL.md` 顶部的「子代理通用调度协议」中，不在每个 `agents/*.md` 里重复抄写 |
| `SKILL.md` 调用卡 | `SKILL.md` 的每个委派步骤必须使用统一的 5 项结构化调用卡（`子代理文件`、`触发条件`、`并发与权限`、`传入槽位映射`、`状态闭环与主流程出口`），不得只写一句模糊的“加载 `agents/xxx.md`” |
| 模型语义档位 | 统一使用语义档位 `inherit`（继承父会话模型）、`fast`（轻量快速）、`strong`（深度推理与审查），不写死单一平台的私有模型 ID；当子代理因推理复杂度返回 `BLOCKED` 时支持按规则升级为 `strong` 重派；宿主不支持指定模型时回退为 `inherit` |
| 上下文白黑名单 | 统一使用全新独立上下文（`inherit_context: false`）。每个子代理必须显式列出「允许传递（具名槽位 `[SLOT_NAME]`）」与「禁止传递（污染项）」，即使宿主不支持底层上下文隔离参数，也由主代理在组装提示词时强制隔离 |
| 首行状态码契约 | 按子代理的决策性质采用两套正交的首行状态码之一：<br>1. **产出型（探查 / 选题 / 实施）**：`DONE` \| `DONE_WITH_CONCERNS` \| `NEEDS_CONTEXT` \| `BLOCKED`<br>2. **判定型（审查 / 合规 / 验收）**：`PASS` \| `NEEDS_REVISION` \| `NEEDS_CONTEXT` \| `BLOCKED` |
| 降级防伪红线 | 当前运行环境不支持子代理时，主代理仅使用「允许传递」的槽位信息按同一份 `prompt` 自己执行，并向用户如实声明，**严禁**声称结果来自独立子代理 |

## 二、目标技能需要的文件

| 目标文件 | 来源模板 | 职责与内容 |
|----------|----------|------------|
| `SKILL.md` 中的「子代理通用调度协议」+ 各步骤「轻量委派调用卡」 | `assets/subagent-kit/skill-dispatch.md` | 通用调度协议每个 `SKILL.md` 写一次（约 18 行）；每个委派点放一张 5 行结构化调用卡，显式展示传入槽位映射与主流程出口 |
| `agents/<role-id>.md` | `assets/subagent-kit/agent-role.md` | 单文件自包含子代理定义：YAML 头部 + 1. 调度配置 + 2. 上下文与任务输入 + 3. 结果验收与状态闭环 + 4. ```` ```prompt ```` 纯提示词代码块 |

## 三、工作流

### 模式 A：给新技能设计子代理委派

在 `--create` 确认技能包含需要独立上下文、多路并行或零历史包袱审查的环节后进入：

1. **识别子代理边界与决策性质**：
   - 仅在满足以下任一条件时拆分子代理：① 探索或检索过程会产生大量中间噪音污染主会话；② 多个互不重叠的子任务可并行加速；③ 需要零历史包袱的独立审查者把关。主代理核心决策与用户交互留在主会话，不为凑阶段而滥设子代理。
   - 确定每个子代理属于**产出型**（返回 `DONE` / `DONE_WITH_CONCERNS` / `NEEDS_CONTEXT` / `BLOCKED`）还是**判定型**（返回 `PASS` / `NEEDS_REVISION` / `NEEDS_CONTEXT` / `BLOCKED`）。
2. **定义输入槽位与禁传清单**：
   - 为每个子代理收敛最小必需的具名槽位 `[SLOT_NAME]`，并明确哪些主会话信息（如创作历史、上一轮审查报告、主观预判）属于禁止传递项。
3. **套用模板生成文件**：
   - 按 `assets/subagent-kit/skill-dispatch.md` 在 `SKILL.md` 中写入通用调度协议与各步骤的轻量委派调用卡。
   - 按 `assets/subagent-kit/agent-role.md` 为每个角色生成 `agents/<role-id>.md`，替换全部占位符并删去模板注释与未选用的状态码分支。
4. **验证**：执行第四节的检查清单。

### 模式 B：把已有技能改造为统一子代理约定

当已有技能出现以下任一问题时使用本模式改造：
- `SKILL.md` 中只有模糊的一句话调用，看不出调度配置与传入槽位（原 `human-writing` 模式）；
- 子代理提示词写死了 `Task tool (general-purpose):` 等单一平台语法，或将专属输入表与 `prompt` 拆散在多个文件导致同步困难（原 `openspec` 模式）；
- 技能自己的 `agents/` 目录下混放了 `template.md` 等非运行时模板文件；
- 每个 `agents/*.md` 重复抄写相同的等待去重、超时与降级套话。

**改造步骤**：

1. **盘点现状**：列出目标技能 `SKILL.md` 中的所有委派点，以及 `agents/`（或 `*prompt*.md`）下的全部子代理文件。
2. **对照约定列差异**：对照第一节的 9 项约定，逐项列出「已符合 / 需修改」及具体调整方式，展示给用户确认后再执行修改。
3. **执行重构**：
   - 在 `SKILL.md` 中补齐「子代理通用调度协议」，并将各处的子代理调用改写为统一的 5 项「轻量委派调用卡」；
   - 将分散的子代理文件统一收敛至 `agents/<role-id>.md`，按 `assets/subagent-kit/agent-role.md` 结构重组为「YAML 头部 + 1. 调度配置 + 2. 上下文与任务输入 + 3. 结果验收与状态闭环 + 4. ```` ```prompt ```` 代码块」，删去各文件中重复的通用调度套话与绑定单一平台的调用头；
   - 删除目标技能 `agents/` 下的 `template.md` 等编写期模板文件。
4. **验证**：执行第四节的检查清单。

## 四、检查清单

`SKILL.md` 侧：

- [ ] 包含「子代理通用调度协议」且只出现一次，明确规定仅提取 `agents/<name>.md` 第 4 节 ```` ```prompt ```` 代码块发送给子代理
- [ ] 每个委派步骤均采用包含 `子代理文件`、`触发条件`、`并发与权限`、`传入槽位映射`、`状态闭环与主流程出口` 的结构化调用卡
- [ ] 调用卡中的槽位名与对应 `agents/<role-id>.md` 第 2 节、第 4 节中的 `[SLOT_NAME]` 完全一致

`agents/<role-id>.md` 侧：

- [ ] `agents/` 目录下仅有真实运行时子代理文件，无 `template.md` 等模板文件残留
- [ ] YAML 头部包含 `name`、`description`、`model`（取 `inherit` / `fast` / `strong`）、`inherit_context`
- [ ] 第 1–3 节（主代理层）与第 4 节 ```` ```prompt ```` 代码块（子代理层）边界清晰，````` ```prompt ```` 内部无主代理闭环逻辑泄漏
- [ ] 第 2 节同时列出了「允许传递（具名槽位）」与「禁止传递」
- [ ] 第 3 节的状态流转表与第 4 节提示词首行规定的 4 个状态码逐字对齐
- [ ] 第 4 节提示词内没有任何绑定单一宿主平台的工具名（如 `Task tool`、`subagent_type`）或未说明的裸占位符
