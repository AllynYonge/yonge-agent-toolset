# 重写模式 - 技能文档重写方法论

## 核心定位

在**不改变技能行为**的前提下，通过结构重组、内容分层、歧义消除和规范化处理，提升技能文档的清晰度、可维护性和指令遵从率。

重写的对象是文档本身（SKILL.md + references），而非技能的功能逻辑。重写前后，技能在相同输入下应产出相同输出。

| 允许 | 禁止 |
|------|------|
| 调整段落顺序和层级结构 | 增删功能或改变技能意图 |
| 将过长正文拆分到 references/ | 引入原文不存在的新策略或框架 |
| 合并重复/冗余指令 | 改变工作流步骤的逻辑顺序 |
| 将模糊表述替换为精确表述 | 删除有效的约束条件 |
| 统一术语和概念命名 | 添加原文未暗示的新约束 |
| 移动关键规则到首尾位置（认知位置优化） | 改变输出格式的核心要求 |
| 补充缺失的章节分隔和导航标记 | 改变角色设定或技能身份 |
| 将写死的同构条目抽象为可插拔数据 | 改变触发条件或适用范围 |
| 添加引用链接和阅读时机说明 | 重新设计技能的方法论（道/法层） |

## 工作流

### 步骤1：功能基线提取

读取目标技能的 SKILL.md 及其所有 references/ 文件，提取并记录：

1. **核心意图（道）**：技能为什么存在？解决什么 Claude 原生处理不好的问题？
2. **方法论（法）**：技能采用什么策略、框架或心智模型？
3. **功能清单（术）**：逐项列出所有独立功能和模式（每个用一句话描述）
4. **约束清单**：所有正向和负向约束
5. **工作流逻辑**：各步骤的顺序、依赖关系和条件分支
6. **输出规格**：各模式的输出格式要求

此基线是最终验证的锚定标准——重写结果必须覆盖基线中的每一项。

### 步骤2：技能诊断

MUST 参考"技能编写指南"章节列出的全部原则逐一检查目标技能。该章节是原则清单与判据的唯一来源。

**诊断规则：**
- **仅展示实际存在问题的维度**：无问题的维度在表格后简要列出，不占表格行
- **每个维度可以有多个问题**：每个问题单独占一行，有独立的严重度和证据
- **证据必须精确**：必须引用原文章节名或行号，不能凭空断言
- **问题描述应独立可理解**：不依赖表格其他行的上下文
- **严重度评估应一致**：同类问题在不同维度中的严重度应保持可比性

**诊断每个原则时，依次完成：**
1. **判定总体状态**：**有问题** / **无问题**
2. **若有问题，逐条罗列**（一个维度可能存在多个独立问题）：
   - 定位原文具体位置作为证据
   - 评估该问题的严重度：
     - **高**：严重影响指令遵从率、可维护性或运行结果
     - **中**：有明显改进空间，但不会立即导致功能失效
     - **低**：细微瑕疵或风格不统一
   - 描述修复后的预期效果

向用户展示诊断报告后，**MUST 等待用户明确选择要修复的维度**，然后进入步骤3。

**在用户回复前，禁止：**
- 直接执行任何重写操作
- 自行决定修复哪些维度

### 步骤3：针对性重写执行

仅对用户选定的维度执行重写。按以下优先级处理（高优先级先做，因为后续维度可能依赖其结果）：

1. **结构组织规范** — 基础骨架正确后，其他维度才有稳定的定位
2. **渐进式披露** — 内容分层决定了哪些内容留在正文
3. **扩展性** — 消除坏味道可能涉及文件拆分
4. **指令放置** — 在最终结构上做认知位置调整
5. **交互式引导** — 流程和可执行性优化
6. **原则优先** — 把只覆盖已知情况的枚举提升为覆盖一类情况的判断标准（在重点解释性之前做：一条规则该不该存在，先于它该怎么措辞）
7. **重点解释性** — 措辞和解释层面的改进（补齐缺失的 WHY，把只说"不要做什么"的规则改写为正向表述）
8. **术语一致性** — 最终抛光
9. **表达精简** — 在其他维度修复完成后执行精简（若选择了此维度，参考 [simplify.md](simplify.md) 中的精简技巧）

### 步骤4：基线验证和变更总结

逐项核对步骤1提取的功能基线：

- [ ] 每个功能点在重写后仍存在且可被识别
- [ ] 每个约束条件未被删除或弱化
- [ ] 工作流逻辑和步骤顺序未改变
- [ ] 输出格式要求完整保留
- [ ] 核心意图未发生偏移
- [ ] 参考文件引用路径正确且可到达

如果其中任何一项不满足要求，回退后再次进行修正。完成所有修正工作后，请一并附上变更说明概要。

## 输出规范

### 用户选择前（诊断报告）

```markdown
## 功能基线

- **核心意图**：[一句话]
- **功能清单**：
  1. [功能1]
  2. [功能2]
  ...
- **约束清单**：
  1. [约束1]
  2. [约束2]
  ...
- **工作流逻辑**：[简要流程描述]

## 诊断报告分析

| # | 维度 | 严重度 | 发现的问题 | 证据 | 预期效果 |
|---|------|--------|-----------|------|----------|
| 1 | 渐进式披露 | 高 | SKILL.md 正文 580 行，超过 500 行建议上限 | L1-L580 | 拆分详细参考到 references/，加快加载速度 |
| 2 | 渐进式披露 | 中 | 第三方 API 详细调用示例（150 行）全部写在正文 | §API 使用 / L200-L350 | 移到 references/api-examples.md |
| 3 | 扩展性 | 高 | 五个平台的处理逻辑硬编码在正文并列段落 | §平台适配 / L400-L480 | 拆成 references/platform-*.md，正文只保留选择逻辑 |
| 4 | 指令放置 | 中 | 核心约束"禁止修改用户原文"出现在文档中段 | L320 | 移到 frontmatter 后首段（首因效应） |
| 5 | 术语一致性 | 低 | "子智能体" / "子agent" / "subagent" 混用 | §工作流 / L50, L68, L90 | 统一为"子智能体" |
...

**无问题的维度：** 交互式引导、重点解释性、结构组织规范

请选择要执行的维度（输入序号如 `1,3,4` 或 `all`，或 `cancel` 放弃重写）：
```
