# 统一配置约定 - 所有带配置技能共用的设计原则、格式约定与改造流程

## 核心定位

配置类文档的主要失败模式不是报错，而是**静默失效**。用户按文档写下了完全合法的配置，或者两个技能各自设计了不同的配置位置与覆盖顺序，技能却当配置不存在——没有任何提示，表现为「我明明配了却没生效」。这类问题的排查成本远高于配置本身的复杂度，因为用户没有任何线索可循。

本文件将配置的设计原则落实为一套跨技能的统一约定：**同一个根目录、同一种文件格式、同一条优先级链、同一套三层文档模板、同一份读取脚本。** 所有带配置的技能都按这一套编写，用户只需要记住一个位置、一种写法，也不会因为各技能的规则分叉而配错。

> 本文件是 SKILL.md `### 配置设计（条件适用）` 与 `## 统一配置（--config）` 小节的展开。

## 一、约定与设计原则

| 项目 | 约定与判据 |
|------|------------|
| 适用门槛 | 目标技能存在以下任一情形时适用：① 需要持久化用户偏好（默认值、开关、路径）；② 需要凭据或密钥入口；③ 需要在多个后端 / 平台 / 供应方之间选择。三者皆无则整块跳过，不为「将来也许会有配置」预留结构 |
| 根目录 | 项目级 `<cwd>/.yonge/.yonge-skills/`，用户级 `~/.yonge/.yonge-skills/` |
| 偏好文件 | `<根目录>/<技能名>/EXTEND.md`，内容写在 YAML front matter 里，第一个字段是 `version: 1` |
| 查找顺序 | 项目 → 用户，命中第一个就停，**不合并** |
| 密钥文件与隔离 | 密钥统一放 `<根目录>/.env`（所有技能共用一份），**只能**放 `.env`，禁止写进 `EXTEND.md`。读取脚本发现密钥类字段会直接报错 |
| 优先级单行声明 | `CLI 参数 > EXTEND.md > 进程环境变量 > 项目 .env > 用户 .env > 内置默认值`。写成单行链条且与实现逐字对齐；文档承诺的每一个查找位置，实现必须真的去查，否则会造成静默忽略或在硬门禁下重复提问 |
| 三层按需承载 | 按被读时机切分三个承载位置：<br>1. **主文件（SKILL.md 步骤 0）**：只写查找路径链、字段概括、密钥位置、优先级及指向下层文档的指引（每次执行都要判断，压到约 15 行常驻上下文）；<br>2. **schema 文档（`preferences-schema.md`）**：字段类型、取值域、默认值、写法限制（仅在读写配置时按需加载）；<br>3. **首次设置文档（`first-time-setup.md`）**：问什么、选项怎么排、答案怎么落盘（仅在首次设置或补问时加载）。<br>**判据**：一段配置内容若在 90% 的执行里都用不到，就不该留在 `SKILL.md` |
| 缺失硬门禁与两分支补问 | 把配置加载写成阻塞步骤（`## 步骤 0：加载偏好配置 ⛔ 阻断`），避免模型在缺配置时静默挑选默认值；门禁只阻断需要配置的操作，不需要配置的操作（如只预览主题）直接放行。<br>配套两分支判定：**没有配置文件**走完整首次设置（流程 A）；**已有配置但必需字段为空**只补问那一个字段（流程 B），避免改一个字段重答整套问题 |
| 字段命名与可变项映射 | 默认值用 `default_*`；批量相关放 `batch.*`；按后端区分的字段建模成映射 `default_model.<后端>`，不要预先组合成 `<后端>_model`。<br>**判据**：新增一个后端时只需改一处即为达标；若要在多处各加一行，说明「后端」和「字段」两个可独立变化的维度被预先乘在了一起 |
| 环境变量与多入口对齐 | 技能私有变量用 `<技能名大写>_<字段>`（如 `YONGE_VIDEO_GEN_MAX_WORKERS`）；第三方服务密钥沿用服务商通行名称（如 `ARK_API_KEY`）；多账号密钥用 `<前缀>_<别名>_<KEY>`（别名转大写、非字母数字转下划线，找不到时回退到 `<前缀>_<KEY>`）。<br>字段表必须设「等价环境变量」列，标明 CLI 参数、配置文件字段与环境变量的对应关系，防止用户当成三套独立机制重复配置 |
| 清单单一事实来源 | 可选值清单（后端名单、模型名单、枚举取值域）、字段表与结构说明只在一处写定（`preferences-schema.md`），其它位置一律写「见 X」，消除多处抄写导致的漂移与自相矛盾 |
| 示例不含默认值 | 默认值只出现在字段表的「默认值」列；示例只展示用户真正需要覆盖的字段，另给一个最小示例示范「最少写多少就能运行」，防止用户照抄完整示例后将默认值固化在本地 |
| 声明格式约束 | 只要解析器不是标准库完整实现，文档就必须交代实际容忍的写法边界（缩进要求、行内注释规则、flow/inline 映射与数组、未知键与非法值的报错或忽略方式），防止合法配置被静默丢弃 |
| 生效回显 | 每次执行前输出一行实际使用的关键值，例如「使用 ark / 模型 X」 |

### 关键细节与示例

1. **反直觉优先级规则必须显式举例**（否则读者会按直觉理解）：
   - **EXTEND.md 覆盖环境变量**：EXTEND.md 写了 `default_model.ark: A`，环境变量写了 `ARK_VIDEO_MODEL=B`，最终用 A。
   - **项目 .env 覆盖用户 .env**：两边都写了 `ARK_API_KEY` 时，用项目级的。

2. **可变项建模成映射，不要预先组合**：
   ```yaml
   # 正确：映射式 —— 新增一个后端只加一行
   default_model:
     alpha: null
     beta: null

   # 错误：组合式 —— 新增一个后端要加 N 行，且分散在多处
   alpha_model: null
   alpha_concurrency: null
   beta_model: null
   beta_concurrency: null
   ```

## 二、目标技能需要的文件

| 文件 | 来源模板 | 内容 |
|------|----------|------|
| SKILL.md 中的「步骤 0」 | `assets/config-kit/step0.md` | 查找表、两种情况的处理、字段概括、密钥位置、优先级，约 15 行 |
| `references/config/preferences-schema.md` | `assets/config-kit/preferences-schema.md` | 字段表（字段 / 类型 / 默认值 / 等价环境变量 / 说明）、最小示例、密钥变量表、写法限制 |
| `references/config/first-time-setup.md` | `assets/config-kit/first-time-setup.md` | 流程 A 完整设置、流程 B 只补问缺失字段 |
| `scripts/lib/skill-config.ts` | `assets/config-kit/skill-config.ts` | 读取脚本，**原样复制，不在目标技能里修改** |
| `scripts/lib/skill-config.test.ts` | `assets/config-kit/skill-config.test.ts` | 可选，随读取脚本一起复制 |

没有脚本的技能（只靠模型读文件执行）也需要前三个文件。读取脚本可以只当检查工具用：`bun <路径>/skill-config.ts --skill <技能名>`。

### 读取脚本的用法

```ts
import { getConfigValue, loadDotEnv, loadSkillConfig, pickFirst, resolveSecret } from "./lib/skill-config";

loadDotEnv(); // 先把 .env 写入环境，进程里已有的变量不覆盖
const { config, source, warnings } = loadSkillConfig({
  skill: "my-skill",
  allowedKeys: ["version", "default_provider", "default_model.*", "batch.max_workers"],
});
for (const warning of warnings) console.error(`警告：${warning}`);

// 按优先级链取值：CLI > EXTEND.md > 环境变量 > 内置默认值
const model = pickFirst(args.model, getConfigValue(config, "default_model.ark") as string, process.env.ARK_VIDEO_MODEL, "builtin");

const apiKey = resolveSecret({ prefix: "ARK", key: "API_KEY" });
if (!apiKey) throw new Error("缺少 ARK_API_KEY，请写入 ~/.yonge/.yonge-skills/.env");
```

`source` 为 `null` 表示没找到 EXTEND.md。脚本要不要因此停止，由技能自己决定：模型调用时已经在步骤 0 完成了首次设置，脚本里通常直接用默认值继续即可。

读取脚本已经处理的事情，目标技能**不要**再自己实现：路径查找、YAML 子集解析、版本检查、密钥字段检查、未知字段警告、.env 优先级。

## 三、统一工作流

**适用场景**：为新技能设计配置，或改造已有技能使其符合统一约定。

**核心原则**：所有带配置的技能最终都必须符合第一节的全部约定。从零设计和改造已有实现只是起点不同，核心操作完全相同。

### 步骤 1：定位现状与目标

**新技能**（在 `--create` 的访谈问题 7 确认需要配置后进入）：

- 逐项列出配置需求，按性质分为三类：
  - 偏好（默认值、开关、路径）→ `EXTEND.md`
  - 密钥 → `.env`，文档中只记录变量名
  - 每次执行都会变化的输入 → CLI 参数，不进配置文件
- 确定门禁范围：哪些操作必须先有配置，哪些可以直接放行
- 现状 = 空白，目标 = 完整的三层配置文档与读取闭环

**已有技能**（配置路径、格式、优先级或写法未统一时触发改造）：

- **盘点现状**：列出技能实际读取的所有配置入口，包括文档写了的和代码实际读取的，两边都要查。逐项记录路径、格式、优先级、密钥位置
- **对照约定**：对第一节的每一项给出「已符合 / 需修改」，需修改的写明当前做法与目标做法
- **展示差异，等待确认**：把差异表交给用户，**确认后再进入下一步**。涉及用户已有配置文件的移动或改写时，单独说明影响

### 步骤 2：设计字段表与交互规则

**无论新建还是改造**：

1. **定义字段表**：按映射式建模多后端可变项（`default_model.<后端>`），补齐每个字段的类型、默认值与等价环境变量
2. **收敛单一事实来源**：将可选值清单集中在 `preferences-schema.md`，其它文档只写引用
3. **设计首次设置与补问**：梳理流程 A（完整设置问题与保存位置选择）和流程 B（必需字段为空时只补问单字段）

### 步骤 3：生成或重构文件与读取逻辑

- **文档层**：按第二节套用 `assets/config-kit/` 下的三个模板（`step0.md`、`preferences-schema.md`、`first-time-setup.md`），替换全部 `{{...}}` 占位（改造已有技能时，用模板重写原有配置相关段落）
- **代码层**（有脚本时）：原样复制 `assets/config-kit/skill-config.ts` 到 `scripts/lib/`，用 `pickFirst` 按优先级链取值，`allowedKeys` 与字段表保持一致；改造已有技能时，替换并删除原有的路径查找、YAML 解析和 `.env` 加载函数
- **旧配置迁移**（仅改造已有技能时适用）：
  - 路径变化时，文档写明旧路径；不在读取脚本里加旧路径兼容，避免读取规则再次分叉
  - 用户已有的配置文件，**由用户确认后**再移动或改写，不擅自处理
  - 密钥原来写在 `EXTEND.md` 里的：告诉用户改写到 `.env` 的哪个变量名，由用户自己写入，之后再删除 `EXTEND.md` 里的对应字段

### 步骤 4：验证与实测

执行第四节的检查清单。若改造的已有技能存在用户真实配置，用真实配置跑一遍检查命令；若解析器有任何自定义扩展，直接喂入刁钻片段实测实际行为，将测出的真实边界回写到 `preferences-schema.md` 的「写法限制」小节。

## 四、检查清单

文档：

- [ ] 步骤 0 的查找表、优先级与本文件第一节一致，按三层承载位置切分且主文件控制在约 15 行
- [ ] 字段表有「等价环境变量」列；默认值只出现在字段表里；按后端区分的可变项使用映射式而非预先组合
- [ ] 示例只写需要覆盖的字段，并有一个最小示例
- [ ] 可选值清单只写在一处，其它位置引用
- [ ] 任何文档、示例里都没有密钥的值，也没有把密钥写进 EXTEND.md 的示例
- [ ] 首次设置的最后一问是保存位置；有流程 B（只补问缺失字段）
- [ ] 写法限制一节与读取脚本的实际行为一致

代码（有脚本时）：

- [ ] `scripts/lib/skill-config.ts` 与 skill-creator 中的版本完全一致（`diff` 无输出）
- [ ] 没有残留的自写路径查找、YAML 解析、.env 加载
- [ ] `allowedKeys` 覆盖字段表里的全部字段
- [ ] 每次执行前输出实际使用的关键值

实测（验证解析器边界，防止静默丢弃或静默透传）：

- [ ] `bun scripts/lib/skill-config.ts --skill <技能名>` 能读取到用户的真实配置
- [ ] 删除（或改名）EXTEND.md 后，技能会进入首次设置，而不是静默使用默认值
- [ ] 喂入边界片段实测：未知字段（得到警告）、合法但非常规的 flow 映射 `{a: 1}`（报错）、密钥字段 `api_key: x`（报错）、高于支持版本的 `version`（报错）、带行内注释的值与非常规缩进层级（行为与「写法限制」声明一致）
- [ ] 写一个逐行列表与一个行内数组 `[a, b]`，都能正确解析成数组
- [ ] 技能原有的测试全部通过
