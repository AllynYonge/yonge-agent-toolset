# 环境适配说明

## Claude.ai 特定说明

在 Claude.ai 中，核心工作流相同（起草 → 测试 → 审查 → 改进 → 重复），但因 Claude.ai 没有子智能体，部分机制需要调整。需要适配的点如下：

**运行测试用例**：没有子智能体就无法并行执行。对每个测试用例，先读取技能的 SKILL.md，再按其中指令亲自完成该测试提示词。一次只做一题。这不如独立子智能体严格（技能是你写的，又是你在跑，上下文完整），但仍是有用的健全性检查——人工审查步骤可弥补不足。跳过基线运行——直接用技能按要求完成任务即可。

**审查结果**：若无法打开浏览器（例如 Claude.ai 的 VM 无显示器，或你在远程服务器上），完全跳过浏览器审查器。改为在对话中直接呈现结果。对每个测试用例，展示提示词与输出。若输出是用户需要查看的文件（如 `.docx` 或 `.xlsx`），保存到文件系统并告知路径，便于其下载检查。内联征求反馈：「这个看起来怎么样？有什么想改的吗？」

**基准测试**：跳过定量基准测试——它依赖基线对比，没有子智能体时意义不大。专注于用户的定性反馈。

**迭代循环**：与之前相同——改进技能、重跑测试用例、征求反馈——只是中间没有浏览器审查器。若有文件系统，仍可将结果组织到各迭代目录中。

**描述优化**：该部分需要 `claude` CLI 工具（具体是 `claude -p`），仅在 Claude Code 中可用。若在 Claude.ai 上，跳过。

**盲测对比**：需要子智能体。跳过。

**打包**：`package_skill.py` 在任何具备 Python 与文件系统的环境都能运行。在 Claude.ai 上可以执行它，用户可下载生成的 `.skill` 文件。

**更新现有技能**：用户可能是在要求你更新已有技能，而非新建。此时：

- **保留原名称。** 记下技能目录名与 `name` frontmatter 字段——保持不变。例如已安装技能为 `research-helper`，则输出 `research-helper.skill`（不要写成 `research-helper-v2`）。
- **编辑前先复制到可写位置。** 已安装技能路径可能只读。复制到 `/tmp/skill-name/`，在副本上编辑，并从该副本打包。
- **若手动打包，先在 `/tmp/` 暂存**，再复制到输出目录——直接写入可能因权限失败。

## Cowork 特定说明

若你在 Cowork 中，需要知道的主要事项如下：

- 你有子智能体，主工作流（并行拉起测试用例、跑基线、评分等）均可使用。（若遇到严重超时，可以改为串行跑测试提示词，而不是并行。）
- 你没有浏览器或显示器：生成评测查看器时使用 `--static <output_path>`，写出独立 HTML 文件，而不是启动服务器。然后提供用户可点击的链接，在浏览器中打开该 HTML。
- Cowork 环境往往容易让 Claude 在跑完测试后跳过生成评测查看器。再强调一次：无论 Cowork 还是 Claude Code，跑完测试后务必用 `generate_review.py` 生成评测查看器（不要自己手写一套 HTML），让人先看到样例，再修订技能。重要：在自行评估输出*之前*先生成评测查看器——尽快把结果放到人面前。
- 反馈机制不同：没有常驻服务器时，查看器的 "Submit All Reviews" 按钮会下载 `feedback.json` 文件。你可以从该文件读取反馈（可能需要先申请访问权限）。
- 打包可用——`package_skill.py` 只需要 Python 和文件系统。
- 描述优化（`run_loop.py` / `run_eval.py`）在 Cowork 中应可正常工作：它通过 subprocess 调用 `claude -p`，不依赖浏览器。但请等技能完全做完、且用户确认状态良好后再做这一步。
- **更新现有技能**：用户可能是在要求你更新已有技能，而非新建。遵循上文 Claude.ai 小节中的更新指引。
