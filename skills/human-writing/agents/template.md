# [任务名称]子代理

[一句话说明本任务做什么、返回什么、不做什么。]

在 SKILL.md「[触发位置]」中派发，任务 ID 为 `[task-id]`。[其他派发条件，无则删去。]

本文件包含三部分：开头的元数据（模型与上下文继承等属性）供主代理配置调度参数；正文的调度规则、上下文、任务输入、结果验收与主代理闭环服务主代理；末尾「任务提示词」是交给子代理的全部内容。Never 把「主代理闭环」写入任务提示词或传给子代理。

## 调度规则

- **派发**：用当前环境提供的子代理工具创建一个新任务，只发送填充好的任务提示词。若当前调度工具支持指定模型参数，按开头元数据 `model` 配置；不支持或模型不可用时，回退为继承父会话模型（`inherit`）。子代理[只读 / 可写入的文件范围]，不联网、不向用户提问、不再创建子代理；工具支持限制权限时同时在调度参数里限制。
- **上下文隔离**：若当前环境工具支持配置上下文继承，当 `inherit_context: false` 时显式关闭继承；无法关闭时仅在任务提示词中提供下方「允许传递」的信息，禁止附带父会话历史。
- **必须得到结果**：[是 / 否，及原因]
- **并行**：[单任务 / 可与哪些任务并行 / 必须等待哪些任务]
- **执行中**：子代理不得回问，信息不足时按任务提示词的错误格式返回。[主代理是否允许向原任务追加指令，允许时写清触发条件，且不得改变任务目标或扩大任务范围]
- **无法派发时**：[主代理按同一份任务提示词自己执行，只使用下方「允许传递」的信息，并如实声明 / 停止任务 / 向用户说明]。Never 声称结果来自独立子代理。
- **等待与去重**：只采用子代理的最终结果；工具日志、中间消息、出错前的部分输出都不算。等待超时、调度出错时保留原任务继续等待或修正调用，不重新派发同一任务。完成通知与主动查询得到的是同一份结果，不重复处理。
- **结束**：结果用完后，停止仍在运行且不再需要的任务。
