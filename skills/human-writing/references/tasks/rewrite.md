# 改用户交来的原稿

这份文件用于用户交来一篇已经写好的稿子，要求润色、去掉 AI 味、改得像人写的，或者按平台改写。原稿按 AI 生成处理。先保住原稿里的事实，再动句子。

## 改写深度

`--deep` 决定对原稿动多大的手，默认 `low`。取值按 SKILL.md 第 1 步的配置优先级解析，无法识别的值直接报错并列出三个档位，不静默回退。

| 档位 | 含义 | 约束对象 | 典型场景 |
|------|------|----------|----------|
| `low`（默认） | 表层改写 | 下一节的锚点全部保护 | 去 AI 味、润色、换表达 |
| `medium` | 中度改写 | 只保护核心事实锚点，释放示例和过渡 | 替换论据、重排段落、增删支撑细节 |
| `high` | 结构复刻 | 不提取语义锚点，改为提取结构蓝图 | 借用原文骨架，以全新内容重写 |

`medium` 和 `high` 引入的新论据、案例和数据，只能来自用户材料或检索到的可核验来源，不补造例子（见 SKILL.md「内容靠什么站住」）。虚构题材可以按 `references/craft/fiction.md` 创造。

`high` 有开放条件，新内容必须有来处。现实题材需要用户提供新材料，或者能检索到足够的可核验来源，重新盘点材料。现实题材没有新材料时不开放 `high`，改用 `low` 或 `medium`，并告诉用户原因。

## 动手前记下不能改的东西

通读一遍，在内部记下下面这些信息。改完以后逐条对照，含义不能变。

- 名称、人名、机构名和产品名。
- 日期、时间线和事件先后。
- 数字、价格、比例和排名。
- 因果主张和对比关系。
- 引语。
- 否定、限制条件和立场的正负。
- “可能”“据说”“目前来看”这类不确定说法。原稿说到几成，改完还说到几成。
- 用户写下的亲历、情绪和判断。

原稿里没有来源的断言，可以降低语气或删去，不能替它补出处。

按档位决定保护范围。

- `low` 保护上面全部。
- `medium` 只保护前四项里的名称、日期与时间线、数字、因果主张。示例、过渡段落、支撑性论据的具体措辞、对比关系的具体表述方式都可以改。允许替换论据、重排段落顺序、增删支撑细节，只要核心事实不变。
- `high` 不提取锚点，改为提取结构蓝图，见下文「结构复刻」。用户同时指定了具体的保护要求，比如“数据不要动”，照样保护这些内容。

## 先圈出已经活着的地方

找出原稿里有人味的部分，原样保留或只做最小改动。

- 具体而少见的细节。
- 真实的矛盾情绪。
- 自然的插话、补充和自我修正。
- 作者反复使用的口头禅和用词习惯。
- 明确的个人判断，哪怕说得偏。

作者的日常用词不要换成更正式的词。无伤大雅的小毛病可能就是他的声音，不为了显得顺滑而改掉。没有配置风格时，原稿自己的声音就是这次的风格。

## 硬禁令直接执行

原稿命中 SKILL.md「成稿绝对不能出现」里的任何一项，直接按禁令改写，不向用户确认，也不因为原稿反复这样写就当成作者习惯保留。上一节要保留的地方命中禁令时，同样改写，只保住它原本的事实和判断。

## 合规清单和原稿冲突时

有合规清单时，动手前逐条核对原文的标题、主张、例子和行动建议。修复需要删除受保护信息或改变立场时，先列出冲突原文、对应规则和可选方向，等用户确认。不为合规伪造来源，也不只换词掩盖原有的功效暗示。

## 逐段重写

`low` 和 `medium` 这样改。

一段一段处理。读完一段，用一句话说出它想表达什么。随后不看原文，按这句话重新写。写完对照前面记下的清单，确认事实、限制和语气强度没有走样。`low` 对照全部锚点，`medium` 只对照核心事实锚点。

逐词替换只能换掉表面的词，句子骨架还是原来的。骨架本身没有问题的段落，只改命中的那几处。

有目标平台时，把平台文件的「起草侧重」叠加上去，比如小红书笔记要重点前置、单点聚焦。

## 结构复刻

`high` 这样改。

先提取原文的结构蓝图，逐段标注每段承担的功能角色。

| 段落功能 | 示例 |
|----------|------|
| 开场设问 | 抛出悬念或痛点 |
| 场景铺设 | 建立具体情境 |
| 论点陈述 | 亮出核心主张 |
| 举例论证 | 用案例支撑论点 |
| 数据佐证 | 用数字增强说服力 |
| 转折/递进 | 推进或翻转论证方向 |
| 情感共鸣 | 连接读者感受 |
| 总结收束 | 收尾给出收获或行动 |

提取后形成段落功能序列（如：开场设问 → 场景铺设 → 论点陈述 → 举例论证 × 2 → 转折 → 新论点 → 总结收束）。这个序列是改写的骨架约束，用全新内容填充每个功能槽位，但保持序列不变。同时记录原文的修辞节奏特征（段落长短交替模式、短句密集区与长句舒展区的分布），作为节奏参考。

执行方式：

1. 逐个功能槽位创作：按段落功能序列依次填充，每个槽位产出对应功能的新段落。
2. 内容来源：SKILL.md 第 3 步定下的论点和切入角度（改稿默认以原文论点为起点）。新的论据、案例和数据只能取自用户材料、检索到的可核验来源，或虚构题材中按 `references/craft/fiction.md` 创造的内容。某个功能槽位没有材料可填，就合并或删掉这个槽位，不编造。
3. 节奏参考：参照原文的修辞节奏特征（段落长短交替、句式密度变化），但不拘泥于精确复制。
4. 不对照原文内容：原文的具体事实、例子、数据全部可替换，约束对象是结构，不是语义。

结构蓝图是指导而非牢笼。如果某个功能槽位在新论点下显得多余或不自然，可以合并相邻槽位或微调功能，但整体叙事节奏应与原文同构。

## 长稿逐节处理

超过 `long_threshold` 的稿子，新写和改稿都按标题或主题分节处理。每完成一节，做一次跨节一致性检查。

1. 回读前一节最后两句加当前节开头两句，检查语气温度是否断裂（如前节冷静分析，当节突然煽情）。
2. 对比当前节与前一节的句式节奏。如果两节的平均句长和段落长度近似，主动打破其中一节的节奏。
3. 检查用词重复。如果同一个“过渡词”或“态度词”在相邻两节都出现，替换其中一处。
4. 全部段落完成后，快速通读首段和末段，确认全文的情感弧线连贯（起点到终点之间有推进，而非平行重复）。

## 改完以后

按 `references/quality/revision.md`「什么时候做哪几层」检查。少于 500 字的短改稿只做句子层，其余改稿三层都做。压缩试验和删段只针对没有材料托住的部分，前面圈出的活着的地方不删。
