# 文件输出与多形态聚合

本文件定义成稿怎样保存为文件、草稿态怎样标记，以及同一篇内容的多个「平台 × 媒介」形态怎样聚合到一个文件。这是跨形态的文件编排规则，不属于任何单个发布形态。形态约束见 `references/publish/platforms/`。SKILL.md「七步流程」第 7 步读取本文件。

## 保存规则

| 条件 | 行为 |
|------|------|
| 未配置 `output_dir` | 仅在对话中输出，不保存文件 |
| 已配置 `output_dir` | 新写或改稿完成后，保存至 resolver 返回的 `output_dir`，文件名为 `{title}.md`。有目标平台时，文件内容以 `# {platform}-{medium}-draft` 作为顶级标题标记草稿态，文章标题用二级标题 `## {title}` 紧跟其后；没有目标平台时只写 `# {title}` |
| 文章通过最终复审正式交付时 | 把分区标题的 `-draft` 后缀去掉，如 `# xhs-note-draft` 改为 `# xhs-note` |

文件名始终是 `{title}.md`，草稿态只标在文件内的分区标题上，不改文件名。

`# {platform}-{medium}` 分区标题是文件编排标记，不是正文，`check_prose.ts` 不对它报错。

## 分区命名规则

同一篇内容的多个形态聚合在一个 Markdown 文件里，用 H1 分区区隔，不散成多个独立文件。

分区标题由平台和媒介在运行时拼接而成。

```
# {platform}-{medium}
```

- 平台用全名（`wechat`、`xhs`），与 `references/publish/platforms/{platform}-{medium}.md` 文件名中的平台部分一致，不用缩写。
- 媒介用媒介名（`article`、`note`），与同一文件名中的媒介部分一致。
- 平台与媒介之间用一个连字符分隔。媒介名内部可以含连字符，如 `short-video`。平台名只含小写字母，所以第一个连字符就是平台和媒介的边界。
- 草稿态在分区标题后加 `-draft` 后缀，该形态通过审核正式交付时去掉。

解析锚点正则：`^# (?P<platform>[a-z]+)-(?P<medium>[a-z-]+?)(?P<draft>-draft)?$`

### 组合示例矩阵

| platform | medium  | 分区标题               | 说明     |
| -------- | ------- | ------------------ | ------ |
| wechat   | article | `# wechat-article` | 公众号长文  |
| wechat   | note    | `# wechat-note`    | 公众号短图文 |
| xhs      | note    | `# xhs-note`       | 小红书笔记  |

组合是运行时叉乘，不预先枚举。新增平台或媒介数据文件后，其组合分区名按上述规则自动成立，无需改本文件。

## 追加规则

触发条件：用户提供源文件路径，并且要求转写或适配为另一种形态（如公众号长文已发布，再写小红书笔记）。满足时按下列规则执行。

1. **就地追加**：追加目标是用户给出的那个源文件本身。Never 新建文件，Never 写到 `output_dir` 另存。
2. **首次转写归位**：若源文件还是普通正文、没有任何形态分区标题，先把原正文整体归入 `# wechat-article` 分区（原文视为已发布的公众号长文），再在其后追加目标形态分区。
3. **目标分区已存在**：直接覆盖重写该分区内容。Never 保留旧版本，Never 追加成第二份。
4. **只动目标分区**：Never 改写、精简或顺手优化其它形态分区的已有内容，也 Never 重命名其它分区。
5. **形态转换而非搬运**：转写正文按目标「平台 × 媒介」约束重新组织（长文转小红书笔记要做信息裁剪与重点前置，不是原文照搬）。写作风格沿用 active profile，跨平台跨媒介不变（`references/publish/overview.md`「两条分开处理的原则」）。
