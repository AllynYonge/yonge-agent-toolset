# 改写工作流

使用本文件执行改写模式。

## 改写模式

## 1. 加载偏好设置

在向用户提问之前，调用 resolver 获取最小 active profile 配置：

```bash
python3 skills/human-media-writer/scripts/resolve_preferences.py \
  --workspace-dir "{workspace_dir}" \
  [--profile "<name>"]
```

resolver 内部优先读取项目级 `{workspace_dir}/.human-media-writer/EXTEND.md`，再读取用户级 `$HOME/.human-media-writer/EXTEND.md`。只使用脚本返回的 active profile、风格、长度和审核参数；不要直接读取完整 EXTEND.md。

### 2. 确定选题（不可跳过）

委派选题子代理 `references/topic-selection-prompt.md` 进行选题。

即使用户已经从分析模式选定了某个方向，本步骤仍然不可跳过——分析产出的"选题方向"只有灵感来源和切入策略，还不是可执行选题（缺少精确的读者画像、核心论点句、内容结构预判和标题方案）。选题子代理会评审并锐化这个方向，产出 3 个可执行方案供用户做最终选择。跳过这一步等于在模糊角度上直接改写，结果往往偏离用户真实意图。

传入参数：

- `[MATERIAL]`：待改写原文全文、用户修改要求、必要背景
- `[CANDIDATE_TOPIC]`：原文核心角度、用户指定的新方向，或分析模式传入的选题方向；**如果来自分析模式，填入用户选定方向的标题 + 核心论点 + 切入策略**；如果都没有则留空
- `[PROFILE_CONTEXT]`：active profile 中的 `positioning`、`audience`、`purpose`；没有则填"（空）"
- `[MODE]`：`rewrite`

主代理原样呈现子代理返回的结果，等待用户选定；随后，将用户所选方案中的关键信息提取并注入后续步骤：
- "目标用户与场景" → 补充信息收集中的目标读者
- "内容结构" → 指导第9步正文构建
- "核心论点" → 作为第7步核心论点的起点
- "关键词与标签" → 指导标题和SEO优化

### 3. 提取语义锚点 / 结构蓝图

本步骤根据 `--deep` 档位执行不同操作：

#### --deep low（默认）：提取语义锚点

在改动任何内容之前，从原文中提取以下信息并在内部标记为不可改变的锚点：

- 名称、人名、机构名、产品名
- 日期、时间线和事件顺序
- 数字、价格、比例、排名
- 因果主张
- 对比关系
- 引述性陈述
- 否定、限制条件和极性（正面/负面立场）
- 不确定性标记（"可能"、"据说"、"目前来看"）
- 用户提供的个人经历
- 明确的情感倾向和价值判断

以上信息在改写后必须在含义上保持不变。

#### --deep medium：缩减锚点范围

仅保护以下核心事实类锚点：

- 名称、人名、机构名、产品名
- 日期、时间线和事件顺序
- 数字、价格、比例、排名
- 因果主张

以下信息释放为可改动：示例、过渡段落、支撑性论据的具体措辞、对比关系的具体表述方式。允许替换论据、重排段落顺序、增删支撑细节——只要核心事实不变。

#### --deep high：提取结构蓝图

不提取语义锚点。改为提取原文的**结构蓝图**——逐段标注每段承担的功能角色：

| 段落功能 | 示例 |
|----------|------|
| 开场设问 | 抛出悬念或痛点 |
| 场景铺设 | 建立具体情境 |
| 论点陈述 | 亮出核心主张 |
| 举例论证 | 用案例支撑论点 |
| 数据佐证 | 用数字增强说服力 |
| 转折/递进 | 推进或翻转论证方向 |
| 情感共鸣 | 连接读者感受 |
| 总结收束 | 收尾给出收获或行动 |

提取后形成段落功能序列（如：开场设问 → 场景铺设 → 论点陈述 → 举例论证 × 2 → 转折 → 新论点 → 总结收束）。这个序列是改写的骨架约束——后续步骤 6 用全新内容填充每个功能槽位，但保持序列不变。

同时记录原文的修辞节奏特征（段落长短交替模式、短句密集区与长句舒展区的分布），作为节奏参考。

### 4. 风格

按优先级确定写作风格：

1. 用户本次请求中的显式风格指令（最高优先）
2. resolver 返回的 active profile `custom_style`（内联自定义风格）
3. resolver 返回的 active profile `writing_style`（内置风格预设名）
4. `default` 风格预设（兜底）

使用 resolver 返回的 `style` 获取具体声音参数。若用户提供了写作样本要求模仿，或需要从样本提取风格结构，按 SKILL.md §写作风格系统 的自定义风格结构与样本提取流程执行。

### 5. 平台

从用户信号中确定目标平台：

| 信号 | 平台 |
|------|------|
| 公众号/微信/长文/深度 | 微信 |
| 小红书/xhs/笔记/种草 | 小红书 |
| 无信号 | resolver 返回的 active profile `platform`，再无则默认微信 |

确定后按 SKILL.md §平台形态 应用对应约束（段落长度上限、开篇模式、内容密度要求、读者注意力模型）。

### 6. 改写

本步骤根据 `--deep` 档位执行不同策略：

#### --deep low / medium：重写而非修补

去AI味的正确方法不是逐词替换——是把原文意思理清后，用中文本来的说法重新说一遍。逐词修补只能消除表面信号，无法解决句法骨架层面的翻译腔。

执行方式：
1. 读完一个段落后，合上原文，用一句话说清楚"这段想表达什么"
2. 用这个核心意思作为锚点，重新组织语言——不要看着原文改
3. 改完后对照锚点清单，确认事实未丢失（`low` 对照全部锚点；`medium` 仅对照核心事实锚点，其余可自由发挥）

逐段重建文章。这不是简单的短语替换：

- 重组段落，使每个段落承担不同的功能
- 变化句式节奏（短句、中句、长句、片段句）
- 用具体场景或实例替代抽象表述
- 移除 AI 词汇簇（参见 `references/ai-tell-catalog-zh.md`）
- 保留原文论证的逻辑和推进过程
- 保留作者的真实的例子和数据不变（`medium` 模式下允许替换论据和示例，只要核心事实不变）

#### --deep high：结构复刻

在步骤 3 中已提取原文的段落功能序列和修辞节奏特征。本步骤以该结构蓝图为骨架，用全新内容填充每个功能槽位。

执行方式：
1. 逐个功能槽位创作：按段落功能序列依次填充，每个槽位产出对应功能的新段落
2. 内容来源：选题诊断（步骤 2）选定的方向提供核心论点和切入角度；围绕该论点生成新的论据、案例、数据和表述
3. 节奏参考：参照原文的修辞节奏特征（段落长短交替、句式密度变化），但不拘泥于精确复制
4. 不对照原文内容：原文的具体事实、例子、数据全部可替换——约束对象是结构，不是语义

注意事项：
- 结构蓝图是指导而非牢笼——如果某个功能槽位在新论点下显得多余或不自然，可以合并相邻槽位或微调功能，但整体叙事节奏应与原文同构
- 如果用户同时指定了具体的语义保护要求（如"数据不要动"），在对应槽位中保留该内容

#### 长内容跨节一致性（所有档位通用）

对于长内容（超过 long_threshold）：按标题或主题段落逐块处理。每完成一个段落后执行跨节一致性检查：

1. 回读前一节最后两句 + 当前节开头两句，检查语气温度是否断裂（如前节冷静分析，当节突然煽情）。
2. 对比当前节与前一节的句式节奏——如果两节的平均句长和段落长度近似，主动打破其中一节的节奏。
3. 检查用词重复：如果同一个"过渡词"或"态度词"在相邻两节都出现，替换其中一处。
4. 全部段落完成后，快速通读首段和末段，确认全文的情感弧线连贯（起点 → 终点之间有推进，而非平行重复）。

### 7. 委派审核子代理

改写完成后，按 `references/reviewer-workflow.md` 的「审核子代理模板」派发独立子代理进行质量审核，然后按其「迭代修订协议」执行修复→再审循环，直到满足终止条件。
