# 委派子代理任务规范

本文件说明如何通过当前会话的运行时工具，把边界明确的任务动态交给子代理：派发、等待、检查结果、处理异常。  

业务流程说明“做什么”，本文件说明“怎么委派”，`references/subagents/adapters/` 说明“当前 Agent 环境用什么工具”。

## 必读：委派步骤

1. **准备**：读取任务说明，填充任务提示词（输入 + 参考文件）。
2. **选 Agent 平台**：按当前会话实际工具选择 `references/subagents/adapters/` 规则；无匹配则用 `generic.md`。
3. **能力检查**：确认当前子代理工具能否满足任务要求的身份标识、上下文、权限、通信、续接、结果获取以及调度与执行限制；不能满足硬要求则直接走备用方式。
4. **派发**：创建子代理，只发送已填充的任务提示词。
5. **保存 ID**：保存第一次返回的子代理 ID 或等效标识。
6. **等待**：仅在下一步确实需要结果时等待；同步返回的平台无需额外等待。
7. **检查**：按任务说明「结果验收」检查；通过后交回业务流程。
8. **结束**：按平台实际能力停止仍在运行且不再需要的任务；仅在提供显式关闭 / 释放能力时关闭。同步返回或自动结束的平台无需额外调用。
9. **备用**：无法派发或运行时能力不满足任务硬要求时，执行任务说明中的备用方式。

以上是步骤名，不是工具名。

---

## 子代理任务说明

任务说明只服务主代理。子代理只接收已填充的**任务提示词**。

新建或更新的任务说明必须包含：

1. **基本信息**：任务 ID、目标、是否必须得到结果、无法派发时的备用方式  
2. **Agent 选择**：任务所需职责、权限、硬性平台能力、允许的降级方式和并行关系  
3. **交互模式**：按事件填写（派发 / 执行中 / 结果验收后 / 可选主代理闭环 / 结束）；未写则默认一次性完成，仅平台支持针对原 ID 触发续接时允许补充一次缺失内容  
4. **上下文方式**：全新独立 / 最小相关 / 继承父会话；允许与禁止传递的内容  
5. **任务输入**：主代理如何填充占位符（必须 / 可选 / 缺失时）  
6. **结果验收**：格式与必有结构（状态→动作写在交互模式，避免重复）  
7. **任务提示词**：完整、自包含正文——角色、目标、输入、参考文件、行为限制、输出格式都写在这里  

尚未迁移的既有任务说明缺少「Agent 选择」时，主代理只能根据其已写明的角色、上下文方式和行为限制做保守判断；不得据此推断未声明的硬性平台要求。  
后续修改该任务说明时应补齐模板字段。

默认单任务执行。仅当业务流程同一时刻涉及多个子代理任务时，才在业务流程中写清并行 / 顺序 / 汇总关系；不必写进每个任务说明。

优先使用业务流程已提供的子代理任务说明。若未提供，参考 `references/subagents/task-template.md` 动态构建一份完整子代理任务说明后再派发；不得跳过模板字段或只给一句模糊指令。

## 如何选择平台规则

1. 看当前会话实际提供了哪些子代理工具，不根据模型名猜测。  
2. 读取创建、等待、消息投递、续接、停止和关闭工具的实际 Schema；这些能力应分别判断，不因存在创建工具就假设其它能力存在。  
3. 在 `references/subagents/adapters/` 中选最匹配当前环境的文件。  
4. 无匹配则用 `references/subagents/adapters/generic.md`。
5. 新增 Agent 环境时只新增一个适配器文件，不改业务流程和本文件。

## 运行时能力检查

派发前按任务硬要求逐项确认；任务不依赖的能力可以不要求平台提供。

| 能力 | 检查内容 |
|------|----------|
| 创建 | 是否存在可靠的子代理创建工具 |
| 身份 | 是否返回可复用的 Agent ID、任务名或等效标识 |
| Agent 类型 | 是否存在满足任务职责和权限要求的已注册类型 |
| 上下文 | 是否支持任务要求的不继承、有限继承或完整继承 |
| 权限 | 写文件、联网、工具使用和再次委派能否由平台强制限制 |
| 通信 | 能否向仍在运行的原 Agent 补充信息 |
| 续接 | 能否针对原 Agent 触发新一轮执行 |
| 等待 | 是否能可靠等待或查询原 Agent |
| 结果 | 是否能区分中间消息、最终结果和终态错误 |
| 生命周期 | 是否支持中断、关闭或释放；各动作的实际语义是什么 |
| 调度与执行限制 | 任务依赖时，确认当前平台对并行数量、递归委派、执行轮次或运行时限提供了哪些限制，以及是否满足任务要求 |

不得把官方文档、历史版本或适配器示例中的默认值当作当前环境事实。当前工具没有公开某项能力时，按“不确定 / 不支持”处理，不自行构造调用方式。

## 运行时能力与限制

任务提示词中的限制与平台强制限制必须区分：

| 限制类型 | 含义 | 处理 |
|----------|------|------|
| 行为约束 | 在提示词中要求禁止联网、写文件、向用户提问或再次委托 | 所有平台都应写入提示词，但不能声称形成安全隔离 |
| 平台强制约束 | 运行时工具通过权限、工具白名单、sandbox、Agent 类型或隔离参数强制执行 | 仅当前 Schema 实际支持时使用 |

若任务把某项限制作为硬性验收条件，而当前子代理工具只能提供行为约束，则视为能力不满足，走备用方式。不得为了单次委托临时创建 Agent 定义、修改平台配置或绕过权限。

除非任务说明明确允许，子代理默认不得再次创建子代理。能在运行时收紧委托工具权限时，同时落实平台限制；不能收紧时至少写入任务提示词，并按任务是否要求硬隔离决定是否可继续。

## 附录：上下文方式

| 上下文方式 | 使用规则 |
|------------|----------|
| 全新独立上下文 | 创建接口支持不继承时显式关闭继承；否则必须确认平台默认就是独立上下文 |
| 最小相关上下文 | 优先不继承，只在任务提示词中传明确需要的背景；接口支持有限继承时也只传必要轮次 |
| 继承父会话上下文 | 仅任务确实依赖完整对话、业务流程明确要求且运行时接口明确支持时 |

环境不能满足要求的上下文方式，或无法确认实际传递范围时，平台规则必须说明并走备用方式。不得静默多传会话历史，也不得把提示词自包含等同于上下文隔离。

## 附录：主代理与子代理如何交互

本节规定主代理和子代理之间允许采用哪些交互方式。

默认采用“一次派发、一次返回最终结果”的方式。只有任务说明明确允许，并且当前平台支持时，才能采用其它方式。

| 交互方式 | 适用情况 | 主代理怎么做 | 子代理怎么做 | 限制 |
|----------|----------|--------------|--------------|------|
| 一次性完成（默认） | 绝大多数任务 | 一次提供完整任务要求，只接收最终结果 | 不在执行途中提问，完成后一次性返回可验收结果 | 信息不足时按失败格式返回，不向主代理或用户追问 |
| 补齐验收内容 | 返回结果缺少字段或格式不符合要求 | 使用原子代理 ID 和能触发续接的能力追加一次指令，只说明需要补齐的内容 | 只补充缺失内容，不重新执行整个任务 | 消息投递不等于触发续接；最多补充一次，仍不符合则 `result_invalid` |
| 继续执行原任务 | 任务说明明确允许，并且平台支持触发原代理继续执行 | 使用原子代理 ID 补充指令或输入并触发原代理新一轮 | 继续完成原任务范围内的工作 | 不得借此改变目标、扩大范围或创建新代理代替原代理 |
| 执行途中提问 | 默认不允许 | — | — | 子代理不得向主代理或用户提问；主代理必须在派发前提供完整信息 |
| 同时接收通知和主动查询结果 | 平台既会推送完成通知，也允许主动查询结果 | 按任务 ID 或子代理 ID 去重，采用最先收到的有效结果进行验收 | — | 后续重复通知只用于更新状态，不得重新派发或重新执行任务 |
| 取消任务 | 不再需要任务结果 | 停止仍在运行的原子代理或停止等待，并保留原任务 ID | — | interrupt / stop 不等于永久关闭；不得因为取消而重新创建相同任务 |

选择规则：

1. 任务说明没有指定交互方式时，使用**一次性完成**。  
2. 验收未通过且平台支持对原子代理触发续接时，可以进行一次**补齐验收内容**；只能投递消息但不能触发执行时不算支持。  
3. 只有任务说明明确允许，并且平台支持时，才可**继续执行原任务**。  
4. 平台不支持任务要求的交互方式时，应使用任务规定的备用方式，或返回对应的内部错误；不得擅自改为重新派发任务。

任务说明应使用**事件表**（见 `task-template.md` 的“交互模式”部分）记录本任务采用的交互约定；本节只定义通用交互方式。  
如果业务流程要求“处理完一个结果后，再派发下一个任务”，应写在任务说明的“主代理闭环”中。这属于多次独立的“一次性完成”，不属于“继续执行原任务”。不要把主代理后续处理步骤写进子代理的任务提示词。

## 附录：多个子代理任务

仅在需要多个任务时使用：

| 关系 | 处理 |
|------|------|
| 相互独立 | 可并行（不超过环境并发上限） |
| 后任务依赖前结果 | 顺序派发；只传必要结果 |
| 共同产生结论 | 并行后由主代理汇总 |
| 任意一个有效即可 | 取得第一个有效结果后按平台规则处理其余 |

并行前提：各自输入完整独立；结果可用任务 ID / 子代理 ID 区分。

- 只读探索、审核和资料整理可以并行，但仍受当前环境并发上限约束。
- 多个 Agent 不得同时修改同一文件或重叠文件范围。
- 写入任务应顺序执行，或使用平台已经提供的可靠隔离工作区；不得为单次任务临时修改平台配置来制造隔离。
- 主代理必须在派发前明确每个写入型 Agent 的文件边界。
- 并发数量、嵌套深度和超时以当前环境实际配置与工具反馈为准，不写死文档默认值。

## 附录：结果检查

取得结果后至少确认：任务 ID、子代理 ID 或等效标识、所用平台规则、终态（成功 / 失败 / 无法执行）、是否通过「结果验收」、失败时的内部错误类型。  
平台提供时还应记录：turn / job ID、父 Agent 或 lineage、执行轮次、terminal status 和 terminal error；未提供时不得自行推断。  
普通消息、活动通知、工具日志、等待中的部分输出和 terminal error 前的不完整文本不得当作最终业务结果。  
业务流程只使用检查后的最终内容。

## 附录：必须遵守的规则

- MUST 每个子代理只做一个边界清楚的任务。  
- MUST 始终使用第一次派发返回的子代理 ID。  
- MUST 按任务 ID / 子代理 ID 去重，避免完成通知与等待返回被当成两份结果。  
- Never 因等待结束、暂未完成或工具调用方式错误而重新派发相同任务。  
- Never 把工具日志、中间推理或已恢复的临时错误当业务结果。  
- Never 把提示词行为约束描述成平台强制权限；能在运行时收紧平台权限时优先收紧。  
- Never 为单次运行时委派临时创建 Agent 定义或修改平台配置来绕过能力限制。  
- SHOULD 只在下一步依赖结果时等待。  
- SHOULD 结果用完后停止仍在运行且不再需要的任务；仅当前平台提供显式 close / release 时执行关闭或释放。

## 附录：常见问题

| 情况 | 内部错误类型 | 处理 |
|------|--------------|------|
| 无可用子代理工具 | `delegation_unavailable` | 执行备用方式 |
| 创建子代理失败 | `delegation_failed` | 平台规则决定是否只重试一次 |
| 等待结束但子代理仍在运行 | `execution_timeout` | 保留 ID，稍后继续等 |
| 子代理明确失败 | `execution_failed` | 按任务说明处理 |
| 找不到委派代理 | `execution_not_found` | 停止等待并报告失败 |
| 委派工具调用方式不受支持 | `orchestration_unsupported` | 修正调用，对委派代理恢复一次 |
| 结果不符合格式 | `result_invalid` | 优先要求委派代理补齐 |
| 停止、关闭或释放子代理失败 | `release_failed` | 保留已有结果，不重复操作 |

内部错误类型用于跨平台一致，面向用户时用自然语言。

### 委派工具调用失败

1. 保留委派代理 ID。  
2. 不得重新派发相同任务。  
3. 按平台规则检查工具名、命名空间、参数。  
4. 已取得 agent ID 时，只允许针对原 ID 修正并重试一次；创建阶段尚未取得 ID 时，是否重试由平台规则决定。  
5. 成功后继续，不展示已恢复的临时错误。  
6. 第二次仍失败则说明环境兼容问题并停止。  
7. 此类错误与等待超时不计入业务流程的有效执行轮次。

### 避免重复处理同一结果

完成通知与主动等待并存时：用任务 ID / 子代理 ID 判断是否同一任务；第一个有效结果进入检查；后续通知只更新状态，不重派、不重跑业务。
