# Codex 子代理委派规则

完成上一级 `protocol.md` 的委派步骤。本适配器只处理当前会话中的运行时委派；实际调用以当前会话完整 Schema 为准。

## 何时使用

- 当前会话实际提供 Codex 子代理创建工具，并能可靠取得最终结果。
- 等待、消息投递、续接、停止或关闭能力按当前 Schema 分别判断，不要求全部同时存在。
- 否则改用 `generic.md`。

## 能力差异

| 能力 | Codex |
|------|-------|
| 创建 | 使用当前 Schema 的创建工具启动子代理线程 |
| 等待 | 使用当前 Schema 的等待工具取得原子代理状态或结果 |
| 消息投递 | 向运行中的原子代理发送信息；不一定触发新一轮执行 |
| 触发续接 | 向原子代理派发 follow-up，使其继续原任务范围内的工作 |
| 停止 | interrupt / stop 只停止当前执行，不等同于永久关闭线程 |
| 关闭 / 释放 | 仅当前 Schema 明确提供 close / release 能力时可用 |
| 上下文 | 创建时按实际参数选择不继承、有限继承或完整继承 |
| 依赖文件 | 同 protocol；优先绝对路径，不可读则完整内联 |
| 完成通知 | 可能主动推送状态，须与等待结果按 agent ID 和执行轮次去重 |

## 委派映射

| 委派步骤 | Codex 处理 |
|----------|----------|
| 派发 | 当前 Schema 实际提供的创建工具 |
| 保存 ID | 保存第一次返回的 agent ID 或 canonical task name |
| 等待 | 当前 Schema 实际提供的等待工具 |
| 补充信息 | 使用当前 Schema 的消息投递能力 |
| 触发续接 | 使用当前 Schema 中能触发原 Agent 新一轮的能力 |
| 获取结果 | 等待返回、完成通知或原 ID 续接后的最终文本 |
| 停止运行 | 仅对仍在运行且不再需要结果的 Agent 使用 interrupt / stop |
| 关闭 / 释放 | 仅当前 Schema 实际提供时执行；不得用 interrupt 模拟关闭 |

调用时使用当前 Schema 的完整工具名和参数，不改写命名空间，不臆造未注册工具。

## 平台特有规则

### 选择子代理类型

按以下顺序选择：

1. 选择当前环境中职责匹配、权限满足的现有自定义 Agent。
2. 无匹配自定义 Agent 时，选择当前创建工具或可用 Agent 列表实际公开的内置类型。
3. 无专业类型时，仅在任务说明允许降级的情况下使用通用 Agent，并在任务提示词中完整定义角色、输入、限制和输出格式。
4. 找不到满足任务硬要求的 Agent 时走备用方式，不遍历不同类型尝试绕过权限。

不得仅凭文档假设 `default`、`worker`、`explorer` 或其它名称当前存在；不得为一次运行时委派临时创建或修改 `.codex/agents/` 定义，也不得套用其他 Agent 环境的类型名。

### 上下文

创建工具提供上下文继承参数时：

| 任务要求 | Codex 处理 |
|----------|----------|
| 全新独立 | 使用不继承模式，只发送已填充任务提示词 |
| 最小相关 | 优先不继承；必要时只继承有限最近轮次，其余背景写进消息 |
| 继承父会话 | 仅任务说明明确要求时使用完整继承模式 |

创建工具未提供继承参数时，以实际平台语义为准，不自行构造继承机制。无论是否继承，任务消息都必须明确目标、边界、输入和输出格式。

### 权限与递归委托

- 子代理继承或获得哪些 sandbox、approval 和工具能力，以当前运行时实际规则为准。
- 提示词中的禁止网络、写文件或再次委托只是行为约束；创建参数能收紧权限时同时落实。
- 除非任务说明明确允许，本次任务提示词必须禁止子代理继续创建子代理。
- 若严格权限隔离是验收条件，而当前子代理工具无法保证，走备用方式。

### Codex 调度与执行参数

Codex 官方配置参考定义了以下全局 Agent 参数：

| 配置 | 官方默认值 | 作用范围 |
|------|------------|----------|
| `agents.max_threads` | `6` | 同时保持打开状态的 Agent thread 数量上限 |
| `agents.max_depth` | `1` | 子代理嵌套深度上限；根线程从 0 开始 |
| `agents.job_max_runtime_seconds` | 未设置时为 `1800` 秒 | 仅作为 `spawn_agents_on_csv` 每个 worker 的默认运行时限 |
| `agents.interrupt_message` | `true` | Agent turn 被中断时，是否向其上下文写入模型可见消息 |

官方只公开了这些字段的类型、默认值和作用范围，没有说明数字字段的最小值与最大值。实际可接受值以当前 Codex 版本的配置校验为准，不自行补充上下限。

派发前根据当前配置、工具 Schema 或实际错误反馈确认：

- 是否已达到 `agents.max_threads`；
- 当前 Agent 所在深度是否允许继续创建子代理；
- 使用 `spawn_agents_on_csv` 时，每个 worker 的运行时限是否满足任务要求；
- 当前工具是否允许子代理继续委派。

除非任务说明明确允许，子代理不得继续创建子代理；当前工具能强制限制时同时落实平台限制。

高推理强度与多 Agent 并行会增加 token、延迟和额度消耗；这属于成本判断，不属于 Codex 调度参数。

### 生命周期与续接

1. 创建后保存原始 agent ID / canonical task name。
2. Agent 仍在运行时，补充信息优先投递给原 Agent。
3. Agent 已完成但需补齐验收内容时，使用能触发原 Agent 新一轮的 follow-up 能力；只补缺失内容。
4. 等待超时只结束本次等待，不表示 Agent 已失败。
5. 中断只停止当前执行，不得自动改派相同任务。
6. 完成通知、等待结果和续接结果按 agent ID 与轮次去重。

### 消息、续接与新任务

| 操作 | 实际含义 |
|------|----------|
| 消息投递 | 向仍在执行的原 Agent 补充信息；不保证触发新一轮执行 |
| follow-up | 针对原 Agent 触发新一轮执行；仅用于原任务范围内的继续执行或补齐验收内容 |
| 新建任务 | 创建新的 Agent；不得冒充原 Agent 的续接 |

消息工具是否能触发采样以当前 Schema 的明确说明为准。只能投递消息但不能触发执行时，不算支持已完成 Agent 的续接。

### 最终结果与终态错误

只有以下内容可以进入业务结果验收：

- 明确标记为最终回答的内容；
- 等待工具返回的完成终态及其对应结果；
- 原 Agent 经 follow-up 后返回的新一轮最终结果。

普通 Agent 消息、活动通知、工具调用日志、等待中的部分输出和 terminal error 前生成的不完整文本不得当作最终结果。  
收到 terminal error 时记为 `execution_failed`，不得把空结果或部分结果标记为成功，除非任务说明明确允许使用部分结果。

### Lineage 与执行身份

当前环境提供线程来源、父子关系、后代查询、turn ID 或 job ID 时，记录这些信息以确认结果归属、区分首次执行与 follow-up，并对完成通知和等待返回去重。  
当前环境未提供时不得自行推断，也不得把缺少 lineage 当作任务失败，除非任务将其列为硬要求。

## 失败处理

### 工具调用方式错误（如缺命名空间或参数不符）

→ `orchestration_unsupported`：保留 agent ID；核对 namespace 与参数；对原 ID 修正一次；再失败则说明兼容问题并停止。Never 重派。

### 等待超时

→ `execution_timeout`：只结束本次等待，子代理可能仍在跑；需要结果时继续等待原 ID。Never 因超时新建子代理。

### 已达到并发数量上限

保留已有 Agent 状态，先等待或停止不再需要的运行中 Agent；不得为同一任务反复创建。实际并发上限以当前环境为准。

### 结果格式不符

优先向原 ID 补一次“只补齐缺失内容”；当前环境无法触发续接或补后仍不符 → `result_invalid`。不重跑完整任务。

### 停止、关闭或释放失败

→ `release_failed`；已有结果仍有效，不对同一 ID 重复操作。

## 结束时机

- 已完成的 Agent 不要求强制关闭。
- 当前环境提供显式 close / release 时，可在结果用完后释放。
- 只提供 interrupt / stop 时，仅用于仍在运行且结果已不再需要的 Agent；不得对已完成 Agent 使用 interrupt 模拟关闭。
