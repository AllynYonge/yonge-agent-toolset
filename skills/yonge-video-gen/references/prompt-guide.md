# 视频提示词写法

## 基本结构

视频提示词的信息结构和图片不同。图片只需描述"画面是什么"，视频还要说"怎么动"。缺了运镜就等于把控制权交给模型：

```
[主体与动作] + [运镜] + [场景与光线] + [节奏/氛围]
```

例：

```
穿米白色风衣的女性从长椅上起身，走向画面右侧的落地窗。
镜头缓慢右移跟随，保持人物在画面左三分位。
黄昏的侧逆光，室内暖光与窗外冷调对比。
节奏舒缓，无剪切。
```

## 运镜词表

具体的运镜词是可控性的主要来源。只写"镜头移动"等于没写。

| 类型 | 词 | 效果 |
|------|-----|------|
| 推 | 推近、缓慢推入、快速推进 | 拉近距离，强化主体 |
| 拉 | 拉远、缓慢拉出 | 揭示环境，收尾常用 |
| 摇 | 左摇、右摇、上摇、下摇 | 机位不动，视角转 |
| 移 | 横移、平移跟随、侧向移动 | 机位平移，跟主体最常用 |
| 跟 | 跟拍、背后跟随、正面跟拍 | 锁主体，动态感强 |
| 升降 | 升镜、降镜、俯冲 | 改变高度与气势 |
| 环绕 | 环绕、半环绕、绕主体旋转 | 展示立体感，人物/产品常用 |
| 固定 | 固定机位、锁定镜头 | 配 `--camera-fixed` 抑制自动运镜 |

再配速度词：缓慢、匀速、快速、逐渐加速。

## 五条实用规则

**一条视频只讲一个动作。** 5 秒装不下"起身—走过去—开门—回头"。拆成 4 条分镜，各自可控，也便于重跑单条。

**时长与动作量匹配。** 单一动作 5 秒够用；复杂动作或需要铺垫的给 8-10 秒；不确定时 `--duration -1` 让模型自适应也是稳妥选择。10 秒以上容易出现主体漂移或动作循环。

**不要写转场。** "切到下一个镜头""画面淡出"这类词会让模型在一条视频里硬切，通常是废片。转场交给后期。

**不要复述人物长相。** 图生视频时最常见的失败是主体动起来之后变了人。写"照片里的女性抬头看向窗外"，不要写"一位年轻东亚女性，鹅蛋脸，大眼睛，抬头看向窗外"——后者会让模型按描述重新合成一个人，而不是让参考图里的人动起来。

**光线变化要显式说。** 模型默认会保持光照稳定。需要"云层遮住太阳导致画面渐暗"这类变化，必须写出来。

## 图生视频的同一性保持

- 明确说参考图里的人/物就是视频主体，不要重新设计或另造一个相似的
- 只描述动作、运镜、场景变化、光线变化
- 多张参考图时说明它们是同一主体的不同角度，共同定义同一性
- 不要拿上一条生成结果的截帧当下一条的参考图（除非用户明确要求）。漂移会累积
- 主体需要显得更年轻/更老时，通过服装、体态、场景表达，不要要求模型改脸

## 多素材编号

有参考素材时，脚本会自动在提示词前面加编号表：

```
参考资产编号：图片1、图片2、视频1。请按这些编号理解提示词中的图片、视频和音频引用。

图片1里的人走进图片2的房间，沿用视频1的运镜节奏。
```

所以提示词里可以直接用"图片1""视频1"来指代，不必描述哪张是哪张。素材顺序就是 `--ref` / `--ref-video` / `--ref-audio` 的传入顺序。

## 迭代方法

**先 480p 试跑。** 用目标提示词跑 480p / 5 秒，确认主体没变形、运镜方向对了。这一步成本只有正片的零头。

**改提示词时固定 seed。** `--seed <n>` 让同参数可复现，这样提示词的改动才是唯一变量。不固定 seed 的话，画面变化分不清是提示词改对了还是随机性。

**升分辨率时不动其他参数。** 只改 `--resolution`，避免引入新变量。

## 已有分镜产物

`commands/video/` 下的分镜脚本助手、关键帧提示词专家、视频生成提示词专家的产物可以直接用：

```bash
${BUN_X} scripts/main.ts --promptfiles shots/s01.md --video out/s01.mp4 --ref kf/s01.png
```

不要二次改写这些提示词——它们已经是定稿，改写会引入偏差。
