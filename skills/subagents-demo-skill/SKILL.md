# 跨平台子代理委派示例技能（subagents-demo-skill）

## 子代理通用调度协议（跨平台执行指令）

凡标有 `[委派子代理]` 的步骤，主代理**必须**按以下四步在独立子会话中执行，严禁在当前主会话直接代劳：

1. **按需读取子代理文件**：仅在执行到对应步骤时，读取该步骤指定的 `agents/<name>.md` 文件。
2. **解析调度与输入参数**：
   - 按该文件开头元数据与「1. 调度配置」设置模型档位（`inherit` / `fast` / `strong`，宿主不支持指定模型时回退为 `inherit`）、上下文隔离（`inherit_context: false`）与文件读写权限。
   - 按「2. 上下文与任务输入」准备允许传递的具名槽位，严禁附带父会话历史或「禁止传递」列出的信息。子代理严禁向用户提问、严禁再次创建子代理。
3. **提取并发送纯提示词**：
   - 仅提取该文件第 4 节 ```` ```prompt ```` 代码块内的文本，替换其中的 `[占位符]` 后，调用当前宿主环境的原生子代理工具（pi `subagent` / Claude Code `Agent` / Codex 内置子代理 / OpenCode `task`）创建独立任务。
   - **严禁**将 ```` ```prompt ```` 代码块之外的主代理调度与闭环说明传给子代理。
4. **状态验收、去重与降级**：
   - 只采用子代理的最终输出，工具日志与中断前的部分输出不作为结果；等待超时或调度出错时保留原任务排查，不重复派发同一任务；结果用完后停止仍在运行且不再需要的子代理任务。
   - 按该文件「3. 结果验收与状态闭环」核验首行状态码并执行对应分支动作。
   - 若当前环境无法派发子代理，主代理仅使用「允许传递」的信息按同一份 `prompt` 自己执行，并向用户如实声明，严禁声称结果来自独立子代理。

## 探查代码现状 `[委派子代理]`

- **子代理文件**：`agents/explorer.md`
- **触发条件**：需要查明代码结构、定位关键文件与调用链路时触发
- **并发与权限**：只读模式；存在多个独立探查目标且目录范围互不重叠时**并行派发**，否则**串行派发**
- **传入槽位映射**：
  - `[TASK_GOAL]` ← 当前待查明的核心问题与完整需求描述
  - `[TARGET_SCOPE]` ← 允许检索和读取的目录或文件路径清单
  - `[KNOWN_CONSTRAINTS]` ← 已知的架构约束、编辑边界或排除项（无则填 `（空）`）
- **状态闭环与主流程出口**：
  - 按 `agents/explorer.md` 第 3 节完成状态验收（`DONE` / `DONE_WITH_CONCERNS` / `NEEDS_CONTEXT` / `BLOCKED`）；
  - 验收通过后，提取报告中的「关键位置与证据清单」与「调用链路或结构关系」进入后续业务流程。
