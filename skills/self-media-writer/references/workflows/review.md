# 审核工作流

本文件定义审核模式入口与场景路由。  
单次审核任务、状态处置与质量把关闭环见 `agents/article-review.md`「结果验收」与「主代理闭环」。

## 审核模式

当用户要求「审核 / check / audit / review」时：

本模式只审合规红线与内容质量。用户只想查 AI 痕迹（「看看像不像AI / 查AI痕迹」）时，告知本模式不做此项检查，请直接使用 `human-rewriter` 技能。

### 0. 加载合规清单

独立审核先调用 `scripts/resolve_preferences.py` 获取 active profile 的 `compliance_guardrails`；创建/改写后的审核沿用当前已确认的任务清单。补入用户本次明确边界，按 `SKILL.md`「合规红线」处理冲突。无额外规则时显式使用 `[]`，解析失败时不继续审核。

### 1. 提取语义锚点

从草稿中提取：名称与机构、日期与时间线、数字、因果、对比、引述、否定与极性、不确定性标记、用户个人经历、明确情感与价值判断——用于判断形式是否服务于内容。

### 2. 执行文章审核任务

将审核任务委派给 `agents/article-review.md` 子代理完成，必须传入完整 `compliance_guardrails`，而非规则摘要或仅条款编号。

### 3. 呈现报告

- **独立审核模式**：向用户呈现完整报告（含改写优先级建议），不自动改写。
- **创建/改写后质量把关**：按 `agents/article-review.md`「主代理闭环」处理，不直接展示内部审核过程。
- 合规逐条结论是通过的必要条件：有违反或待核实项即为 `NEEDS_REVISION`；字数与规避词脚本通过不能替代此项，也不得据此承诺平台必然通过审核。

## 场景路由

收到有效报告后，先按 `agents/article-review.md`「结果验收」处置状态，再按场景决定报告去向：

| 场景 | 审核目的 | 报告去向 |
|------|----------|----------|
| 创建后审查（craft 步骤10） | 质量把关 | 主代理内部处理，用户不可见；`NEEDS_REVISION` → `agents/article-review.md`「主代理闭环」 |
| 改写后审查（rewrite 步骤9） | 质量把关 | 主代理内部处理，用户不可见；`NEEDS_REVISION` → `agents/article-review.md`「主代理闭环」 |
| 独立审核模式 | 诊断呈现 | 合并确定性约束检查 + 报告呈现给用户；不自动修复 |
