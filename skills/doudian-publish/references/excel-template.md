# 上架模板说明

## 生成空模板

```bash
python3 {baseDir}/templates/make-template.py [输出路径]
```

默认输出 `./抖店上架模板.xlsx`，含三个 Sheet：`商品` / `素材命名规范` / `全局默认`。

## `商品` Sheet 列定义

第 1 行是列名（`*` 后缀 = 必填），第 2 行是填写说明，第 3 行起是数据。

| 列 | 必填 | 说明 |
|----|:---:|------|
| 款号 | ✓ | 货品编号，同时写入抖店「货号」，也是素材目录名 |
| 商品标题 | | 留空则脚本按规则生成 15-60 字符（8-30 汉字） |
| 类目 | ✓ | 三级类目全路径，`>` 分隔。例：`服装>女装>时尚套装` |
| 面料材质 | ✓ | 单一材质名，自动补 100%。例：`聚酯纤维` |
| 材质含量 | | 多材质时 `聚酯纤维:90;氨纶:10` |
| 素材目录 | ✓ | 相对 `--root` 或绝对路径。例：`链接图片/0021` |
| 参考图 | ✓ | **直接往单元格里插图片，可多张**；也可改填路径。仅本地参考，不上传抖店。见下文 |
| 规格组名 | ✓ | 第一组规格名，服饰通常为 `颜色分类` |
| 规格值 | ✓ | `|` 分隔，顺序即前台顺序。例：`上衣|裙子|套装` |
| 尺码 | ✓ | `|` 分隔。例：`S|M|L|XL` |
| 价格 | ✓ | `规格值:价格` 形式。例：`上衣:49.9|裙子:59.9|套装:99.9` |
| 库存 | ✓ | `尺码:库存` 形式，全规格共用。例：`S:360|M:350` |
| 库存明细 | | 按规格分设库存，优先级高于「库存」。例：`上衣-S:100|套装-S:60` |
| 商家编码规则 | | 默认 `{款号}-{规格值}-{尺码}` |
| 商品状态 | | `上架` / `下架`，留空取全局默认 |
| 尺码表模板 | | 抖店已存模板名，如 `身高体重`。留空不套用 |
| 运费模板 | | 抖店模板名，如 `偏远区域限购` / `包邮` |
| 备注 | | 不写入抖店，仅供人工记录 |

### 「颜色分类」可能用于部件而非颜色

服饰套装类目常把它当部件维度用（规格值填 `上衣|裙子|套装`），这是类目约定而非通用规则，
详见 [categories/womens-suit.md](categories/womens-suit.md)。其他类目里它就是字面意义的颜色。

非标准色板值（包括部件名）需走「创建类型」自定义 —— 脚本已处理。

### 「参考图」列：支持单元格内嵌多张图片

这一列不走素材目录的文件名规范，**把图片直接插到单元格里就行**，一个单元格可以放多张。

Excel / WPS 里的操作：选中该行的「参考图」单元格 → 插入 → 图片，把图片拖到单元格范围内。

> **支持**：传统的「浮动图片」和 WPS 的「单元格图片」都可以。WPS 单元格图片
> 通常会写成 `DISPIMG("ID_...",1)`，脚本会从 XLSX 内部的 `cellimages.xml`
> 恢复原图。Excel 365 的 `IMAGE()` 外部图片公式不保证含有本地图片二进制，
> 如解析失败请改用传统浮动图片或填写本地图片路径。

`read-plan.py` 会把这些内嵌图片按行列锚点拆出来，导出到：

```
<素材目录>/参考图/参考图01_<内容哈希>.png
```

文件名带内容哈希，**幂等**：重复跑不会累积同一张图，也不会覆盖你手放进去的文件。
导出路径写入 `items[].素材.参考图`。

不想内嵌图片时，这一列也接受**手写路径**（`|` 分隔，相对 `--root` 或绝对路径），
指向目录时收其下全部图片：

```
参考图/爆款A.jpg|参考图/爆款B.jpg
参考图/0021
```

优先级：单元格内嵌图片 > 手写路径。两边都空就进 `errors` 阻断。

**参考图不会被上传到抖店**，不进主图、不进详情图、不进规格图，只供人工对照。

## 素材命名规范

脚本按**文件名前缀**识别用途，不做模糊推断。命名不对就识别不到。

| 文件名 | 用途 | 数量 |
|--------|------|------|
| `主图01.jpg` … `主图05.jpg` | 商品主图，01 为首图 | 3-5 张，必填；脚本会自动处理为 1:1 |
| `详情图01.jpg` … | 商品详情长图 | ≥1 张，建议 5-10 张；缺少不阻断 |
| `SKU_<规格值>.jpg` | 第一组规格的规格图 | 每个规格值 1 张；缺少时默认使用首张主图 |
| `尺码表.jpg` | 尺码表图（放详情图末尾） | 选填但强烈建议 |

要点：

- `SKU_` 后面必须与「规格值」列的值**完全一致**，如 `SKU_上衣.jpg`。
- 参考图不在此表：它走 Excel 单元格内嵌，导出到 `参考图/` 子目录，不会被误识为上传素材。
- 扩展名支持 jpg / jpeg / png。**jfif 需先转换**。
- 主图必须为 1:1，且 ≥600×600px；非 1:1 的规范主图会按短边居中裁剪为 `主图NN_1x1.jpg`，原图保留。
- 目录名建议与款号一致，便于核对。

## `全局默认` Sheet

单款没填的字段回落到这里：

| 配置项 | 默认值 | 是否生效 |
|--------|--------|:---:|
| 品牌 | 对门的猫 | ✓ |
| 运费模板 | 偏远区域限购 | ✓ |
| 商品状态 | 下架 | ✓ |
| 尺码表模板 | 身高体重 | ✓ |
| 商家编码规则 | `{款号}-{规格值}-{尺码}` | ✓ |
| 发货时效 | 48小时 | ✓ |
| 订单库存计数 | 付款减库存 | ✓ |
| 发货模式 | 现货 | ✗ |
| 售后政策 | 7天无理由退货 | ✗ |

标 ✗ 的两项**脚本不写入页面**，取抖店页面默认值。
`read-plan.py` 会在 `未生效配置` 里列出来，`publish.mjs` 启动时也会明确提示。

- **发货模式**：页面上有控件，但页面默认就是「现货」，当前不写。
- **售后政策**：发布页上没有独立控件（只有只读文案），靠店铺级设置。

「发货时效」与「订单库存计数」只在这个 Sheet 里配，「商品」Sheet 没有对应列 ——
这两项实际上是店铺级策略，逐款不同的场景极少。真需要逐款区分时，在「商品」Sheet
手动加同名列即可，`read-plan.py` 会优先用单款值。

### 不在模板里的字段：风格

「风格」（最多 5 项）要**根据主图的视觉特征**选，不是货盘数据，所以不设 Excel 列。
上品时由 agent 看图判定，经 `publish.mjs --styles <json>` 传入：

```json
{ "GZ0021": ["法式", "轻熟风"], "GZ0018": ["辣妹风", "纯欲风"] }
```

选择指引见 [style-options.md](style-options.md)。
不传就跳过（会拉低商品质量分）；传了平台没有的值只打警告、不阻断。

「导购短标题」也不在模板里：它由平台 AI 生成（点输入框右侧 AI 图标，5-7s 后回填）。

## 校验模板

```bash
python3 {baseDir}/scripts/read-plan.py 模板.xlsx [--root 素材根目录] [--sku GZ0021,GZ0027]
```

输出 JSON，含 `defaults` / `items` / `errors`。每个 item 带 `警告` 数组
（如缺规格图）。`errors` 非空时 `publish.mjs` 会直接中止。

这个命令会写文件：把「参考图」单元格里的内嵌图片导出到 `<素材目录>/参考图/`。
这是它唯一的副作用，幂等。
