# 上架模板说明

## 为什么不直接用旧货盘

旧货盘（如 `副本已巳服饰货盘8.6.xlsx`）对自动化不友好，原因：

1. **图片是 WPS `DISPIMG` 嵌入公式**，读不出文件名，无法映射到本地素材。
2. **一款多色拆成多行**，但抖店是「一个商品 + 多规格值」，行与商品不是一对一。
3. **价格单元格塞多个值**，如 `59.9（上衣）/ 39.9（吊带）`，无法机器解析。
4. **库存只按尺码给一组数**，不区分部件，各部件库存不同时表达不了。
5. 缺抖店必填字段：类目、面料材质、品牌、运费模板、发货时效、售后政策。

所以走「一次性迁移 → 之后用新模板」的路子。

## 生成空模板

```bash
python3 {baseDir}/templates/make-template.py [输出路径]
```

默认输出 `./抖店上架模板.xlsx`，含三个 Sheet：`商品` / `素材命名规范` / `全局默认`。

## 迁移旧货盘

```bash
python3 {baseDir}/scripts/migrate-old-plan.py 旧货盘.xlsx -o 抖店上架-已迁移.xlsx [--material-root 链接图片]
```

迁移后**必须人工复核**，脚本会在输出里列出需要处理的点。已知必查项：

| 项 | 原因 |
|----|------|
| 类目 | 统一填了「服装>女装>时尚套装」，非套装款要改 |
| 面料材质 | 统一填了「聚酯纤维」，要按实际吊牌改 |
| 素材目录 | 按款号猜的路径，要核对是否存在 |
| 库存 | 旧表不区分部件，迁移后各部件共用同一库存 |
| 一款多色 | 多行合并成一行，库存按行累加，要核对 |
| 多价单元格 | 只取了第一个价，其余部件价格要人工改 |
| 组合件 | 如「上衣+背心」，自动归类的价格不可靠 |

## `商品` Sheet 列定义

第 1 行是列名（`*` 后缀 = 必填），第 2 行是填写说明，第 3 行起是数据。

| 列 | 必填 | 说明 |
|----|:---:|------|
| 款号 | ✓ | 货品编号，同时写入抖店「货号」，也是素材目录名 |
| 商品标题 | | 留空则脚本按规则生成 15-60 字符（8-30 汉字） |
| 类目 | ✓ | 三级类目全路径，`>` 分隔。例：`服装>女装>时尚套装` |
| 面料材质 | ✓ | 单一材质名，自动补 100%。例：`聚酯纤维` |
| 材质含量 | | 多材质时 `聚酯纤维:90;氨纶:10` |
| 素材目录 | ✓ | 相对 `--root` 或绝对路径。例：`链接图片/0021` |
| 规格组名 | ✓ | 第一组规格名，服饰通常为 `颜色分类` |
| 规格值 | ✓ | `|` 分隔，顺序即前台顺序。例：`上衣|裙子|套装` |
| 尺码 | ✓ | `|` 分隔。例：`S|M|L|XL` |
| 价格 | ✓ | `规格值:价格` 形式。例：`上衣:49.9|裙子:59.9|套装:99.9` |
| 库存 | ✓ | `尺码:库存` 形式，全规格共用。例：`S:360|M:350` |
| 库存明细 | | 按规格分设库存，优先级高于「库存」。例：`上衣-S:100|套装-S:60` |
| 商家编码规则 | | 默认 `{款号}-{规格值}-{尺码}` |
| 商品状态 | | `上架` / `下架`，留空取全局默认 |
| 尺码表模板 | | 抖店已存模板名，如 `身高体重`。留空不套用 |
| 运费模板 | | 抖店模板名，如 `偏远区域限购` / `包邮` |
| 备注 | | 不写入抖店，仅供人工记录 |

### 「颜色分类」用于部件而非颜色

服饰套装的常见做法：把「颜色分类」当部件维度用，
规格值填 `上衣|裙子|套装`，这样一个商品就能分开卖上衣、裙子和整套。

这些值在平台标准色板里不存在，需要走「创建类型」自定义 —— 脚本已处理。

一款多色时把颜色和部件拼起来：`粉色上衣|黑色上衣|裙子|粉色套装|黑色套装`。

## 素材命名规范

脚本按**文件名前缀**识别用途，不做模糊推断。命名不对就识别不到。

| 文件名 | 用途 | 数量 |
|--------|------|------|
| `主图01.jpg` … `主图05.jpg` | 商品主图，01 为首图 | 3-5 张，必填 |
| `详情图01.jpg` … | 商品详情长图 | ≥1 张，建议 5-10 张 |
| `SKU_<规格值>.jpg` | 第一组规格的规格图 | 每个规格值 1 张，必填 |
| `视频01.mp4` | 主图视频 | 选填，≤60s |
| `白底图.jpg` | 白底商品图 | 选填 |
| `尺码表.jpg` | 尺码表图（放详情图末尾） | 选填但强烈建议 |

要点：

- `SKU_` 后面必须与「规格值」列的值**完全一致**，如 `SKU_上衣.jpg`。
- 扩展名支持 jpg / jpeg / png。**jfif 需先转换**。
- 主图 ≥600×600px；详情图宽度 620-1290px；单张 <5MB。
- 目录名建议与款号一致，便于核对。

旧素材目录多为 `1.png` / `4-1.png` / `downloadImg.jfif` 这类混乱命名，
需要按上表重命名后才能用。

## `全局默认` Sheet

单款没填的字段回落到这里：

| 配置项 | 默认值 | 是否生效 |
|--------|--------|:---:|
| 品牌 | 无品牌 | ✓ |
| 运费模板 | 偏远区域限购 | ✓ |
| 商品状态 | 下架 | ✓ |
| 尺码表模板 | 身高体重 | ✓ |
| 商家编码规则 | `{款号}-{规格值}-{尺码}` | ✓ |
| 发货模式 | 现货 | ✗ |
| 发货时效 | 48小时 | ✗ |
| 售后政策 | 7天无理由退货 | ✗ |
| 订单库存计数 | 下单减库存 | ✗ |

标 ✗ 的四项**脚本目前不写入页面**，取抖店页面默认值。填了不会生效，
`read-plan.py` 会在 `未生效配置` 里列出来，`publish.mjs` 启动时也会明确提示。
需要这些字段生效的话，先在抖店后台把店铺默认值设好。

## 校验模板

```bash
python3 {baseDir}/scripts/read-plan.py 模板.xlsx [--root 素材根目录] [--sku GZ0021,GZ0027]
```

输出 JSON，含 `defaults` / `items` / `errors`。每个 item 带 `警告` 数组
（如缺规格图）。`errors` 非空时 `publish.mjs` 会直接中止。
