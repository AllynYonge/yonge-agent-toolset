# 抖店商品批量上架

把「Excel 货盘 + 本地素材目录」变成抖店后台的商品。抖店没有开放上架 API，
所以走 CDP 驱动真实浏览器。这也意味着操作会被平台风控看见，下面三条是硬约束：

1. **首次使用必须先原样输出风险须知**，让用户知情后再动手。
2. **默认走 `--mode draft`**，存草稿让用户在后台复核，确认无误才 `--mode publish`。
3. **改 `scripts/doudian-page.mjs` 前必读 `references/dom-notes.md`**，
 页面上的每个坑都已记在里面，凭直觉改会踩回去。

## 沟通约定

**提问**：需要向用户提问时，按优先级：

1. 优先用当前运行时的内置提问工具（`ask_user_question` / `AskUserQuestion` /
 `request_user_input` 等）。
2. 没有则输出编号列表，让用户回复编号。
3. 支持多问一次的，把所有问题合并成一次调用。

**语言**：用用户的语言回复。技术标识（路径、参数名、字段名、选择器）保持原文。

## 前置条件

### 浏览器

推荐用专用 profile，与日常浏览器隔离，登录态持久保留：

```bash
node {baseDir}/scripts/check-env.mjs --launch
```

`--launch` 会启动或复用 `~/.yonge/doudian/chrome-profile` 里的实例（幂等），
打开后自动检验登录态：已登录直接继续；未登录则打开登录页、抬到前台提示用户扫码，
并轮询等待（默认 300s，`--login-timeout <秒>` 可调）。用户登完脚本自己接上，
**不需要重跑命令**。无人值守场景加 `--no-wait-login`，未登录即以退出码 1 结束。

`publish.mjs` 和 `doctor.mjs` 共用这套逻辑与这两个参数。

浏览器里已开着工作台首页时，脚本会接管那一页而不是另开 Tab，跑完也不关它。

机制细节（Tab 复用规则、`devtools-ws.json` 缓存与 pid 校验、「Allow remote
debugging?」确认框、改用日常浏览器、`cdp-proxy.mjs` 端点冲突）见
`references/browser-setup.md`。

## 工作流

- [ ] Step 0: 展示风险须知 + 跑环境检查（含自动登录检验，未登录会提示并等待）
- [ ] Step 1: 确认数据来源（已有模板 / 新建模板）
- [ ] Step 2: 预检「素材目录」—— 缺失时可选转 `ecom-outfit-lookbook` 生图（见末尾联动章节）
- [ ] Step 3: 校验模板与素材，并自动将非 1:1 主图居中裁剪为 1:1
- [ ] Step 4: draft 批量存草稿
- [ ] Step 5: 人工复核后发布
- [ ] Step 6: 汇报结果

### Step 0: 环境检查

原样输出上面的风险须知，然后按「前置条件 / 环境检查」跑 `check-env.mjs --launch`。

### Step 1: 确认数据来源


| 用户手上有        | 做法                                        |
| ------------ | ----------------------------------------- |
| 本技能的模板 Excel | 直接进 Step 2                             |
| 什么都没有        | 跑 `templates/make-template.py` 生成空模板，让用户填 |


模板列定义与素材命名规范见 `references/excel-template.md`。

### Step 2: 预检素材目录

逐行检查「素材目录」列是否为有效目录。全部有效则直接进 Step 3；
有缺失行时按末尾「与 ecom-outfit-lookbook 联动」章节处理（可选，用户可拒绝）。

### Step 3: 校验模板与素材

```bash
python3 {baseDir}/scripts/normalize-assets.py 模板.xlsx --root 素材根目录
python3 {baseDir}/scripts/read-plan.py 模板.xlsx --root 素材根目录
```

读 JSON 输出，按下表处理：


| 情况                        | 处理            |
| ------------------------- | ------------- |
| `errors` 非空               | 阻断，先修模板再继续    |
| 缺少主图 / 主图无法读取 / 无法处理为 1:1 | 阻断            |
| 缺少参考图                     | 阻断            |
| `items[].警告` 非空           | 向用户报告，不阻断     |
| 缺少详情图                     | 不阻断           |
| 缺少规格图                     | 不阻断，自动回退用首张主图 |


素材必须符合命名规范（`主图01.jpg` / `详情图01.jpg` / `SKU_<规格值>.jpg`），
命名不规范就识别不到，需要先重命名。

参考图直接插在「参考图」单元格里（可多张），或填图片/目录路径。
`read-plan.py` 会把内嵌图导出到 `<素材目录>/参考图/`，**仅供人工参考，不上传抖店**。

`publish.mjs` 在 draft / publish 开始前会再自动处理一次规范主图：非 1:1 按短边
居中裁剪成 `主图NN_1x1.jpg`，原图保留。

### Step 4: draft 批量存草稿

```bash
node {baseDir}/scripts/publish.mjs --plan 模板.xlsx --mode draft --shots ./shots
```

### Step 5: 人工复核后发布

让用户在抖店后台复核草稿。用户确认后：

```bash
node {baseDir}/scripts/publish.mjs --plan 模板.xlsx --mode publish
```

### Step 6: 汇报结果

按「完成汇报」的模板输出。

## publish.mjs 参数

```bash
node {baseDir}/scripts/publish.mjs --plan <货盘.xlsx> [选项]
```


| 参数                    | 说明                |
| ---------------------- | -------------------|
| `--plan <path>`        | 模板 Excel（必填）|
| `--root <dir>`         | 素材根目录，默认取 Excel 所在目录|
| `--sku A,B`            | 只处理指定款号|
| `--mode draft|publish` | 默认 `draft`。draft 存草稿，publish 正式发布                                         |
| `--brand <name>`       | 品牌。优先级：`--brand` &gt; 「全局默认」Sheet &gt; `对门的猫`                             |
| `--styles <json>`      | 风格手动覆盖（一般不用，默认 pi 自动选）：`'{"GZ0021":["法式","轻熟风"]}'`，每款最多 5 项，值必须逐字来自平台当前全集 |
| `--hot-words <json>`   | 热搜词手动覆盖（一般不用，默认 pi 自动选）：`'{"GZ0021":["法式","印花"]}'`，数组 = 有序优先词             |
| `--no-pi`              | 跳过 pi 视觉识别：风格不选（警告），热搜词按平台推荐顺序全点                                          |
| `--launch`             | 用专用 profile 启动/复用浏览器（推荐）                                                  |
| `--port <n>`           | 手动指定调试端口                                                                  |
| `--keep-tab`           | 跑完不关标签页，便于人工复核（复用你已打开的工作台 Tab 时本来就不关）                                     |
| `--shots <dir>`        | 每款保存提交前截图（失败时也存错误截图）                                                      |
| `--resume`             | 跳过状态文件里已成功的款号，见「中断与重跑」                                                    |
| `--report <path>`      | 把结果写成 JSON                                                                |
| `--no-wait-login`      | 未登录直接退出，不等用户登录（CI / 无人值守）                                                 |
| `--login-timeout <秒>`  | 等待登录的上限，默认 300                                                            |


### 中断与重跑

每款的结果会实时追加到 `.<模板名>.state.jsonl`（与模板同目录）。

脚本**不做查重**——同一份货盘跑两次会建出两批同货号商品。所以重跑一定要
加 `--resume`（跳过已成功的款）或用 `--sku` 指定款号。

## 风格与热搜词：默认全自动，看图选在运行时完成

两者都是搜索/推荐匹配的强信号，取决于图片的视觉特征，不是货盘数据，
所以不设 Excel 列。默认流程（单次发布内自动完成，无需传参）：

1. **风格候选集**：打开风格下拉，虚拟滚动收集当前类目**实际可选项**
 （`getStyleCandidates`，运行时事实，比文档快照新）
2. **热搜词候选集**：读推荐区块 `data-kora-exposure` 的 `keyword_list`
3. **一次 pi 调用**：`pi --print --model glm-5.3-flash`（可用环境变量
 `DOUDIAN_PI_MODEL` 覆盖）拿主图 + 两组候选，返回
 `{"风格": [...], "热搜词": [...]}`，脚本过滤到候选内后分别
 勾选/点击。风格挑 2-4 项宁缺勿滥，热搜词最多 6 个
4. **降级**：pi 不可用/超时/解析失败 → 风格跳过+警告（错标签比不选更伤，
 不硬选）；热搜词按平台推荐顺序全点（推荐集本身已是平台生成的）

实测行为详见 `references/dom-notes.md`「风格」与「热搜词推荐」节。

**手动覆盖（一般不用）**：

```bash
node {baseDir}/scripts/publish.mjs --plan 货盘.xlsx --launch \
  --styles '{"GZ0021":["法式","轻熟风"]}' \
  --hot-words '{"GZ0021":["法式","印花"]}'
```

选得不准比不选更差 —— 错的风格标签会把流量引给不匹配的人群。1 项覆盖不足，
贴满 5 项会稀释标签精度。拿不准就只选真万无一失的那一两项，或把图拿给用户确认。

**硬约束：`--styles` 的每个值必须逐字来自平台当前支持的风格全集**
（运行时候选集，或 `references/categories/womens-suit.md` 的快照），
禁止凭语义猜选项名 —— 平台值写法各异（`森系`无「风」字、`日式`/`INS风`各异），
猜错的值会被静默跳过（实测：图是甜美少女感，猜「甜美风」→ 不存在，
正确值是「少女风」）。不在全集里的近似词要么换算成平台名，要么放弃。

风格集随类目变（女装、童装、鞋靴各不相同），但不用提前查：传了当前类目没有的值
只打警告、不阻断，**并且会把该类目实际可选项一并列在日志里**，下次改什么一目了然。
超过 5 项只取前 5 项并上报舍弃的。

## 单款上架的 12 步

`publish.mjs` 对每款执行：


| 步   | 动作                                    | 数据来源                       |
| --- | ------------------------------------- | -------------------------- |
| 1   | 上传主图进入发布流程                            | `主图01.*`                   |
| 2   | 上传辅助图（最多 4 张，新版就在确认页传）                | `主图02-05.*`                |
| 3   | 得到商品标题                                | 平台 AI（不可用时回退到「商品标题」列/规则生成） |
| 4   | 类目由平台自动填充                             | AI 选中后自动带出（回退时才手动选「类目」列）   |
| 5   | 进入完整详情表单（进去后再校对一次主图张数，短了就补传）          | —                          |
| 6   | 面料材质 / 品牌 / 货号                        | 对应列 + `--brand`            |
| 7   | 导购短标题（点输入框右侧 AI）+ 风格多选                | 平台 AI + `--styles`         |
| 8   | 上传详情图                                 | `详情图*.*`                   |
| 9   | 建规格值 + 勾尺码 + 规格图                      | 「规格值」「尺码」列 + `SKU_*.*`     |
| 10  | 填 SKU 价格/库存/商家编码                      | 「价格」「库存」「库存明细」列            |
| 11  | 现货发货时间 / 订单库存计数 / 尺码表模板 / 运费模板 / 商品状态 | 「全局默认」，默认 `48小时` + `付款减库存` |
| 12  | 跑填写检查（仅 publish 模式）                   | 有错误则不提交；draft 跳过此步直接存草稿    |


### 页面版本差异

打开 `/ffa/g/create` 后可能落到两种页面：**新版**先进「智能填写助手」资料页，
**旧版**直接出现首图上传表单。脚本自动识别，新版为主路径、旧版为回退。

差异只在下面四步，第 6-12 步两版完全共用：


| 步   | 新版                               | 旧版              |
| --- | -------------------------------- | --------------- |
| 1   | 上传资料后点「下一步，生成商品」进入智能填写助手         | 直接上传首图          |
| 2   | 在智能填写确认页的主图区传辅助图（1 首图 + 4 空位）    | 在首图表单里传         |
| 3   | 等智能填写助手预填标题和类目（忽略 Excel 标题）      | 点 AI 按钮选第一条推荐标题 |
| 5   | 等「确认信息，继续生成」解除禁用后点击，再等二次 AI 解析完成 | 点「下一步」          |


两版共同的行为约定：自动类目与模板不一致时只记录警告，不覆盖平台识别结果。

新版路径还有一条贯穿全程的约定：**智能填写预填的字段要先清再写**。
品牌会被预填成「无品牌」、面料会多一条不带含量的材质、第一组规格会多一个猜的颜色，
三者都会把草稿搞成带错的。具体表现与处理见 `references/dom-notes.md`
「智能填写的预填值会和脚本打架」节。

## 已知限制

- **不支持主图视频与白底图**。这两项只能在抖店后台手工补。
- **详情图不含尺码表**。当前类目要求详情页有清晰尺码表，目前靠「尺码表模板」
满足校验；想要图片版尺码表需自己放进详情图并命名 `尺码表.jpg`。
这是类目特异项，见 `references/categories/`。
- **规格图缺失时回退用首张主图**，运行日志会提示；要更准确的规格图就补齐
`SKU_<规格值>.jpg`。
- **主图必须为 1:1**。上传前检查，非 1:1 的规范主图按短边居中裁剪为
`主图NN_1x1.jpg`；无法读取或无法处理时阻断。
- **发货模式 / 售后政策取页面默认值**，不按「全局默认」Sheet 覆写，运行时会提示
「不会生效」。发货模式页面默认就是「现货」；售后政策在发布页上没有独立控件，
只能靠店铺级设置。（`发货时效` 与 `订单库存计数` 已实装，不在此列）
- **导购短标题非必填**。它靠平台 AI 生成（无法手填模板化内容），AI 不返回时重试
1 次，仍失败就警告跳过，不阻断上架。
- **参考图不上传抖店**。只作本地记录/对照，不会进主图、详情图或规格图。

## 排障

高频项如下，没命中就查 `references/troubleshooting.md` 全量表。

| 大量 `等待超时` / 选择器找不到               | 抖店可能改版了，跑一次选择器体检（见下），照结果更新 `scripts/selectors.mjs`                          |
| `规格值写入失败` / `SKU 行数不匹配`          | 规格区是最脆的一段，见 `references/dom-notes.md`「规格设置」                                 |
| 草稿里主图只剩 1 张 / 面料报必填 / SKU 多出一组颜色 | 都是智能填写预填值与脚本写入打架（或上传等待过早）。已在 2026-08-31 修复，原因与判据见 `references/dom-notes.md` |
| 草稿被「请输入水洗标/吊牌图」之类卡住              | 那是发布级要求，`--mode draft` 会跳过「填写检查」直接存草稿                                       |
| 耗时比以前长                           | 预期行为。`sleep()` 带 [0.8, 1.75) 随机抖动，单款约 4 分钟                                  |
| `模板缺少必需列: 参考图`                   | 0.4.0 新增的必填列。旧模板补列，或用 `make-template.py` 重新生成                               |


失败时脚本会**保留标签页**（不自动关），方便在浏览器里直接看现场，调试完手动关掉。
配合 `--shots` 还会存一张错误截图。

## 与 ecom-outfit-lookbook 技能搭配

模板里「素材目录」缺失或不是有效目录时，本节适用：可以先用 `ecom-outfit-lookbook` 技能出图，再把产物回填进模板。**这是可选路径，不是必经流程** —— 用户手上已有素材时完全不涉及本节。

**冲突规则：本 SKILL.md 正文的既有规则 > 本节。** 本节只新增一条「没素材时怎么补」的可选前置，不改变 Step 3-6 的任何行为。

`ecom-outfit-lookbook` 的产物目录天然就是一个合法的「素材目录」，不需要改名或转换：

```
<ws>/03-shoots/plan-01/  主图01.png … 主图05.png（1:1）
                         详情图01.png … 详情图03.png ... 详情图-对比图01.png（3:4）
```

它的命名（`主图NN` / `详情图NN`）正是 `read-plan.py` 的识别前缀，且主图生成时就是 1:1，

### 补全缺失的素材目录（可选）

**插在主流程 Step 1 与 Step 3 之间**。当「商品」Sheet 存在素材目录为空或无效路径的行时，可选择调用 `ecom-outfit-lookbook` 生图，或手动补全素材后继续。

#### 1 触发条件与决策

对「商品」Sheet 每一行，检查「素材目录」列：

| 「素材目录」列状态 | 处理 |
|---|---|
| 有值且 `os.path.isdir()` 为真 | **跳过本章节**，该行直接进入 Step 3 正常校验 |
| 空值 / 路径不存在 / 不是目录 | 该行为**候选行**，询问用户 |

不要直接跳到 Step 3 让 `read-plan.py` 报 `缺少主图` —— 那个报错指向的是命名规范问题，会把用户引到错误的排查方向。

**向用户提问**（优先使用运行时提问工具一次问清）：

1. **是否调用 `ecom-outfit-lookbook` 生图**  
   - 选「是」→ 执行生图
   - 选「否」→ 用户手动补素材，完成后回到 Step 3

2. **每个商品裂变出多少个链接**（即多少行 / 多少个方案，对应 `--plans N`）  
   - 输入数字 N（通常 2-5）

#### 2 执行生图

每个候选款号建一个独立工作区，按 `ecom-outfit-lookbook` 自己的 SKILL.md 全流程走（含它的两道硬闸门）。本节不复制它的流程，只约定接口。

##### 2.1 导出参考图到 lookbook 工作区

「参考图」单元格的内嵌图片是原始服饰图的 ground truth。`read-plan.py` 已有 `collect_embedded_images()` + `export_embedded_refs()` 两个现成函数可以导出，但**素材目录还不存在时它写不进去** —— 此时直接把图导到 lookbook 工作区的 `00-input/`。

##### 2.2 调用 lookbook 完整流程

接口约定：

| 传给 lookbook 的 | 取自本模板 |
|---|---|
| 商品名 / 工作区名 | 「款号」列 |
| `00-input/` 原始服饰图 | 「参考图」列的内嵌图片 |
| `--plans N` | §1 与用户确认的裂变数 |

按 `ecom-outfit-lookbook` 技能执行完整流程，产出 `03-shoots/plan-01/` 到 `plan-N/`。

#### 3 裂变 Excel 行

N 个方案 → N 行。**母行复用为第一个方案**（改写它的「素材目录」为 `plan-01` 的绝对路径），只为 `plan-02..N` 新增行。

##### 3.1 裂变规则

- 「款号」全部沿用原款号
- 「素材目录」一律写**绝对路径**（`read-plan.py` 的相对路径是相对 `--root` 解析的）
- 裂变行的其余列（类目、面料、规格值、价格、库存等）**全部复制母行的值**
- 新增行高度 `ws.row_dimensions[r].height = 96`，否则内嵌图会压住其他列

裂变后的形态：

```
款号      素材目录                                  参考图
GZ0021    /abs/ws/GZ0021/03-shoots/plan-01          [内嵌图]   ← 原母行，改写路径
GZ0021    /abs/ws/GZ0021/03-shoots/plan-02          [内嵌图]   ← 新增
GZ0021    /abs/ws/GZ0021/03-shoots/plan-03          [内嵌图]   ← 新增
```

##### 3.2 openpyxl 实现

**问题**：`ws.insert_rows()` 会移动单元格值，但不会移动图片锚点。母行下方每个商品的参考图都会错位到别人的行上，而且 Excel 打开时看起来「有图」，只有逐行核对内容才能发现。实测确认过这个行为。

**解决方案**：先抓取全部图片 → 再插行 → 清空 `ws._images` → 按新行号全部重建。

**关键要点**：
- `XLImage` 必须包 `io.BytesIO`，不能复用抓取时的 `im` 对象（同一个对象被 `add_image` 多次会共享锚点，最后只落一处）
- 母行下方的行号平移 `N-1`，判据是 `s["row"] > MOTHER`（严格大于）
- 改完存盘前先备份原表。openpyxl 重写会丢失它不支持的元素（图表、部分条件格式、数据透视表）；本技能的模板只有数据验证、传统浮动图片，实测可以保住。**WPS 单元格图片是例外，必然损坏**（修复见 §3.3）

<details>
<summary>完整实现代码</summary>

```python
import io
from openpyxl import load_workbook
from openpyxl.drawing.image import Image as XLImage
from openpyxl.utils import get_column_letter

wb = load_workbook(XLSX)          # 不要加 data_only=True，会丢公式
ws = wb["商品"]

# 1) 抓取全部内嵌图（1-based 行列，与 iter_rows 对齐）
shots = []
for im in ws._images:
    frm = im.anchor._from
    shots.append({"row": frm.row + 1, "col": frm.col + 1,
                  "data": im._data()})

# 2) 插行：母行留作 plan-01，只为 plan-02..N 插 N-1 行
ws.insert_rows(MOTHER + 1, amount=N - 1)

# 3) 全部图片按新行号重建 —— 这一步不能省
ws._images = []
for s in shots:
    tgt = s["row"] + (N - 1) if s["row"] > MOTHER else s["row"]
    col = get_column_letter(s["col"])
    img = XLImage(io.BytesIO(s["data"]))
    img.anchor = f"{col}{tgt}"
    ws.add_image(img)
    # 母行的参考图复制进每个裂变行
    if s["row"] == MOTHER:
        for k in range(1, N):
            dup = XLImage(io.BytesIO(s["data"]))
            dup.anchor = f"{col}{MOTHER + k}"
            ws.add_image(dup)
```

</details>

##### 3.3 WPS 内嵌图（fix-cellimages.py）

openpyxl 重存会把 WPS 单元格图片的注册信息剥掉：`[Content_Types].xml` 的 cellimages Override 和 `workbook.xml.rels` 的 cellimages 关系（openpyxl ≥ 3.1 连 `xl/cellimages.xml` 部件本体都会丢）。部件一丢，DISPIMG 失去定义，Excel/WPS 打开后「参考图」列全部变 `#REF!`。实测确认过。

**裂变存盘后必须立即跑**：

```bash
python3 {baseDir}/scripts/fix-cellimages.py <裂变后.xlsx> <存盘前备份.xlsx>
```

脚本从备份（donor）把 cellimages 部件与两处注册信息补回目标文件，并校验全部 DISPIMG 引用都有定义；幂等，可重复执行。

#### 4 已知限制与规避方案

多行同款号是你选定的方案，但它和本技能的既有机制有摩擦，**必须在裂变后告知用户**：

| 机制 | 表现 | 影响 | 规避方案 |
|---|---|---|---|
| `--sku GZ0021` | 会同时命中全部裂变行，无法只跑其中一行 | 🔴 高 | 中断后重跑用 `--sku` 指定其他款号，或先把状态文件 `.<模板名>.state.jsonl` 挪走 |
| `--resume` | 状态文件按款号去重（`readDone` 用款号做 Map 键），第一行成功后其余行会被当成已完成跳过 | 🔴 高 | **裂变批次不要用 `--resume` 重跑**，这一条优先于「重跑必带 --resume」的通用建议 |
| 抖店「货号」 | N 个商品货号相同，后台无法按货号区分方案 | 🟡 中 | 人工在后台按其他字段（商家编码、主图、价格）区分 |
| 商家编码 | 默认规则 `{款号}-{规格值}-{尺码}` 不含方案，N 行会生成完全相同的编码 | 🟡 中 | 改用「原款号 + 方案后缀」（`GZ0021-P01`）命名裂变行 —— 上面四条全部消失 |

当前按用户选定的「沿用原款号」执行。想完全避开摩擦，裂变时改用 `{原款号}-P{序号}` 作为新款号。
