# 多形态聚合输出

本文件定义同一篇内容的多个「平台 × 媒介」形态如何聚合到一个文件、如何就地追加、以及旧命名如何兼容。这是跨形态的**文件编排规则**，不属于任何单个发布形态。形态约束见 `references/media/platforms/`。

## 分区命名规则

同一篇内容的多个形态聚合在**一个 Markdown 文件**里，用 H1 分区区隔，不散成多个独立文件。

分区标题 = **平台维度 × 媒介维度**的运行时拼接：

```
# {platform}-{medium}
```

- 平台用**全名**（`wechat`、`xhs`），与 `references/media/platforms/{platform}-{medium}.md` 文件名中的平台部分一致，不用缩写。
- 媒介用媒介名（`article`、`note`），与 `references/media/platforms/{platform}-{medium}.md` 文件名中的媒介部分一致。
- 平台与媒介之间用**双连字符 `-`** 分隔，媒介名内部若含连字符（如 `short-video`）仍用单连字符——`-` 保证平台/媒介边界不与 `-draft` 后缀或媒介名内连字符歧义。
- 草稿态在分区标题后加 `-draft` 后缀，沿用文件级 `{title}-draft.md` → `{title}.md` 的生命周期约定：该形态通过审核正式交付时去掉 `-draft`。

解析锚点正则：`^# (?P<platform>[a-z]+)-(?P<medium>[a-z-]+?)(?P<draft>-draft)?$`

### 组合示例矩阵


| platform | medium  | 分区标题               | 说明     |
| -------- | ------- | ------------------ | ------ |
| wechat   | article | `# wechat-article` | 公众号长文  |
| wechat   | note    | `# wechat-note`    | 公众号短图文 |
| xhs      | note    | `# xhs-note`       | 小红书笔记  |


组合是运行时叉乘，不预先枚举——新增平台或媒介数据文件后，其组合分区名按上述规则自动成立，无需改本文件。

## 追加规则

触发条件：用户提供源文件路径 **且** 要求转写/适配为另一种形态（如公众号长文已发布，再写小红书笔记）。满足时按下列规则执行。

1. **就地追加**：追加目标是用户给出的那个源文件本身，Never 新建文件、Never 写到 `output_dir` 另存。
2. **首次转写归位**：若源文件还是普通正文、没有任何形态分区标题，先把原正文整体归入 `# wechat-article` 分区（原文视为已发布的公众号长文），再在其后追加目标形态分区。
3. **目标分区已存在**（含旧命名别名）：直接覆盖重写该分区内容，Never 保留旧版本、Never 追加成第二份。
4. **只动目标分区**：Never 改写、精简或"顺手优化"其它形态分区的已有内容，也 Never 重命名其它分区。
5. **形态转换而非搬运**：转写正文按目标「平台 × 媒介」约束重新组织（长文→小红书笔记要做信息裁剪与重点前置，不是原文照搬）；写作风格沿用 active profile，跨平台跨媒介不变（`references/media/overview.md` 关键规则#3）。
