# 技能反馈自动沉淀与清理策略

## 所作决定

自动反馈捕获不再依赖隐式 Skill，而由 Claude Code 与 Codex 的 `UserPromptSubmit`、`Stop` Hook 共用 `$HOME/.yonge-skill/skill-feedback.py` 完成。Hook 只保存状态并启动会话外分析，不向主会话返回内容。仅在反馈可归因到单一、近期明确使用的技能，且揭示可复用问题、具备具体证据和验证方案时，才写入 `$HOME/.yonge-skill/skill-auto-feedback/{skillname}`。只有用户显式执行 `--clearup skillname` 时才允许全量精简、合并和去重；整理结果全部校验通过后，直接删除原始反馈 Markdown，不建立归档。

## 理由

Hook + 会话外单脚本避免把反馈技能的完整说明、判断流程和工具调用注入主会话。严格门控和近期技能归因减少误记录；显式清理命令为破坏性整理提供清晰授权，先生成和校验整理结果再删除原文档，可兼顾直接删除与失败保护。

## 被否决的内容

- 不对普通改写请求、模糊不满、一次性偏好或与技能无关的环境故障自动建档。
- 不自动或定期执行全量清理。
- 不在清理时保留 `archive/`、备份目录或原文档副本。
- 不使用插件、MCP Server、数据库或常驻守护进程实现当前个人版。
- 不由反馈脚本直接修改被反馈的目标技能。
