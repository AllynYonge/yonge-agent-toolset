# human-media-writer 多形态聚合输出

## 决定
同一篇内容的多平台形态聚合进**一个 Markdown 文件**，用 H1 分区区隔，不散成多个独立文件。三种分区：`# wechat-article`（公众号长文）、`# wechat-note`（公众号短图文）、`# xhs-note`（小红书笔记）；草稿态加 `-draft` 后缀（如 `# xhs-note-draft`）。

## 追加规则（转写/适配场景）
触发条件：用户提供源文件路径 + 要求转写为另一形态。
1. 就地追加到用户给的源文件本身，不新建文件、不写 output_dir。
2. 源文件若还是普通正文（无任何形态分区标题），先把原正文归入 `# wechat-article`，再追加目标分区。
3. 目标分区已有内容 → 直接覆盖重写，不保留历史、不追加第二份。
4. 只动目标分区，不碰其它形态已有内容。
5. 按目标形态的 §平台形态约束重新组织，风格跨平台不变。

## 落点
定义在 `SKILL.md` §多形态聚合输出（唯一权威）；`craft-workflow.md` / `rewrite-workflow.md` 的「文件输出规则」表各加一行引用；模式检测表后加转写场景旁注，保证创建/改写两条路径都走聚合规则。

## 理由
用户希望一稿多形态集中管理，覆盖原「新建 {title}-draft.md」默认行为。
